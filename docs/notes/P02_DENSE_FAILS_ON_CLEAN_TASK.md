# dense 在无捷径任务上完全学不动（P0-2 核心发现）

> 2026-10-27 18:20–18:41，MVT-D v2（无捷径），2080Ti。

## 一、现象

`P02_dense1_s{17,53,71}`（dense mid=1，1.397M 参数，24k 步，lr=1e-3）：

| step | loss | dev_r8 |
|---|---|---|
| 4000 | 0.693 | 0.511 |
| 8000 | 0.693 | 0.508 |
| 12000 | 0.693 | 0.475–0.514 |

**loss 恒为 0.693 = ln(2)**，即输出恒为均匀分布。
三个 seed 的 r 扫描完全相同（dense 无循环，符合预期），但准确率停在随机。

## 二、排除配置问题

| 检验 | 结果 |
|---|---|
| 提高 lr 到 3e-3 | loss 仍 0.693 |
| 提高 lr 到 1e-2 | loss 仍 0.693 |
| 手动训练 2000 步（lr 3e-3） | loss 0.695→0.693，**train acc 0.528** |
| 检查 logits 方差 | std=0.177（非恒定，但两候选差异极小） |
| 梯度范数 | 约 0.02（极弱） |

**连训练集都学不会**（train acc 0.528）→ 不是过拟合/泛化问题，是容量或结构问题。

## 三、与历史 dense 的对比

| 实验 | 任务 | dense mid=1 r8 |
|---|---|---|
| `iter4_v2_dense1` | **MVT-5（有捷径）** | 0.817 |
| `remote_C_dense1` | **MVT-5（有捷径）** | 0.824 |
| `P02_dense1`（本轮） | **MVT-D v2（无捷径）** | **0.508** |

**关键解释**：dense 在 MVT-5 上能到 0.82，是因为有**下游链长捷径**可抓
（见 H-023）——它只需比较两候选的链长，一次前向足够。
在没有捷径、必须真走多跳的任务上，**单次前向的 dense 无法完成**。

## 四、这为什么是重要结果

1. **参数效率的直接证据**（但方向与预期不同）：
   不是说"loop 更省参数"，而是**dense 架构根本无法完成这类任务**，
   而 loop 可以（P0-1：hop6 0.755–0.890）。
2. **解释了历史结论为何受污染**：
   MVT-5 的"dense 能到 0.82"完全依赖捷径，不能作为 dense 的能力证据。
3. **支持"循环承载串行计算"**：
   需要多跳的推理必须有多步计算，单次前向（无论多宽）都不够。

## 五、待验证：更宽的 dense 能否救回来

已启动 `P02_dense3_s{17,53,71}`（2.287M）和 `P02_dense5_s{17,53,71}`（3.176M）。

- **若 dense3/5 能学起来**：说明是容量问题，loop 的优势是"参数效率"
  （同样效果用更少参数）；
- **若 dense3/5 也完全不动**：说明是**结构性限制**（单次前向无法承载
  多步串行计算），loop 的价值是"能力"而非"效率"。

两者的论文表述完全不同，必须等结果。

## 六、注意：loop 臂的配方差异

`P02_loop_s{17,53,71}` 用的是 `--ouro --step-sup`，与 P0-1 的 6 seed 相同配置。
但注意 P02_loop 的 seed 是 71/17/53，而 P0-1 是 11/13/19/29/37/43。

**s71/s17 在 P0-1 中没跑过 Ouro**（只在 persist 下跑过）。
所以 P02_loop 的 s71/s17 也是新数据，可用于扩展 seed 统计。

## 七、容量验证：更宽的 dense 同样失败（18:49 更新）

| 臂 | 参数 | 4000 步 loss | 状态 |
|---|---|---|---|
| dense mid=1 | 1.397M | 0.693 | 完全不动 |
| **dense mid=3** | **2.287M** | **0.693** | **完全不动** |
| **dense mid=5** | **3.176M** | **0.693** | **完全不动** |
| loop L=1（对照） | 1.475M | 1.09–1.31（在学） | 8k 时 r8 0.59–0.66 |

**参数从 1.40M 加到 3.18M（2.3 倍），loss 仍然精确停在 ln(2)。**

### 结论修正：不是参数效率问题，是能力问题

原预期："loop 用更少参数达到同样效果" → 表述为**参数效率**。
实际数据："dense 无论多宽都无法完成这类任务" → 表述为**结构性必需**。

这一区分对论文至关重要：
- 若是参数效率 → "循环是更省参数的实现方式"
- 若是结构性必需 → "**循环承载了单次前向无法实现的计算**"

后者是更强的结论，且与本项目最初的假说（循环承载串行深度）方向一致。

### 仍需排除的替代解释

1. **dense 需要特殊初始化/lr**：已测 lr 1e-3/3e-3/1e-2，均不动；
   手动训练 2000 步 train acc 仅 0.528（连训练集都学不会）。
2. **dense 训练不足**：4000 步 vs loop 的同 step 对比，loss 差距是
   0.693 vs 1.09（loop 在下降），不是速度问题。
3. **任务对 dense 不可学**：这正是结论本身——但需注意
   **不能推广为"所有多跳任务 dense 都学不会"**，
   只能说"本任务上 dense 学不会"。MVT-5（有捷径）上 dense 能到 0.82。
