## 二、关键发现：warmup 是"洗牌"而非"提升"

把 Δhop7 按基线是否通过分开看：

| 分组 | seed | Δhop7 |
|---|---|---|
| **基线失败 → 现通过** | 13, 17, 53 | **+0.125, +0.070, +0.220** |
| **基线通过 → 现失败** | 61, 71 | **−0.120, −0.085** |
| 基线失败 → 现失败 | 19, 73 | −0.020, −0.005 |
| 基线通过 → 现通过 | 11, 79 | +0.060, +0.060 |

**净效果接近零**：救回 3 个、弄坏 2 个。

结论修正（H2 初版说法「warmup=1280 提高通过率」**证据不足**）：
**warmup 改变的是"哪些 seed 收敛"，而不是"有多少 seed 收敛"。**
这与 H-029 的观察一致——warmup=1280 的两次运行 task loss 相差 36 倍，
说明它只是把优化轨迹推向不同的吸引子。

**因此**：
1. 论文不能写"warmup=1280 让通过率从 61.5% 提到 X%"——需要更多 seed 才有统计功效。
2. 更可写的表述是：**warmup 是控制优化落点的旋钮**。既然它能在 seed 级别
   大幅改变最终 hop7（±0.22），那"给定 seed 的结果"这件事本身
   高度依赖这个未被识别的超参——这本身是个值得报告的发现。
3. 实用建议：**warmup 应该按 seed 扫，而不是全局固定**。s53 用 1280 拿到 0.915，
   而基线用 960 只有 0.695；反过来 s61 用 960 是 0.895，用 1280 掉到 0.775。
   **每个 seed 的最优 warmup 不同，且差值可达 0.12–0.22。**

## 三、对 H-029「task loss 决定成败」的修正

原规则（warmup=960 上拟合）：task loss < 0.15 → 8/8 达标；≥ 0.21 → 5/5 不达标。

在 warmup=1280 下这条规则**不再干净**：
- s17 task=0.3819 达标（0.810）→ 与"高 task loss 必失败"矛盾
- s83 task=0.0046 但 h7 0.865 <基线 0.905 → 完美拟合训练集也不保证外推
- s19/s73 task 0.36/0.27 不达标 → 符合

**修正后的表述**：task loss 是**必要非充分**条件。
- 必要：13 seed 里 task loss ≥ 0.36 的（19/17）确实失败或勉强；
- 非充分：s17（0.38）达标、s83（0.005）反而低于基线。
即"训练集拟合"是必要条件，"外推"还要看别的东西。

## 四、跨硬件一致性（seed 17 逐点）

AMD 与 3080 基线（warmup 不同）的曲线**形态同构**，含"升档时 task loss 反弹"
（CUDA 0.186→0.368；ROCm 0.221→0.408）。逐点差值 task ≤0.09、r8 ≤0.07、h6 ≤0.13。

**但这不能当作严格的一致性验证**——两跑 warmup 不同（1280 vs 960）。
严格验证需要在同一硬件上用同一 warmup 跑两遍，或在 910B 上用 warmup 960
复现 CUDA 基线的 48 个 loss 点。
