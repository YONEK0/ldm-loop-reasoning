# MVT-D v2 的 0.90 天花板是任务结构造成的（逐 hop 分析）

> 2026-10-27 22:55，基于 `P04_cs48k_s71`（最优 run）。

## 现象

`P04_cs48k_s71` 逐 hop 准确率：

| hop | 训练？ | 准确率 |
|---|---|---|
| 2 | 是 | 0.995 |
| 3 | 是 | **1.000** |
| 4 | 是 | 0.915 |
| 5 | 是 | 0.895 |
| 6 | 是（16k 步） | 0.900 |
| 7 | **否** | 0.915 |
| 8 | **否** | 0.880 |

**不是单调下降**：h7（0.915）> h5（0.895），h3=1.000。

h4–h8 全部落在 **0.88–0.92 的平台**，h2/h3 接近满分。

## 根因：干扰链长度的取值范围随 hop 变化

`s84_dual_task.py`（MVT-D v2）：

```python
max_L0 = hop - 2
L0 = rng.randint(1, max(1, max_L0))   # 干扰链从 e0 出发的额外长度
```

| hop | L0 的取值 | 干扰链总长 | 排除难度 |
|---|---|---|---|
| 2 | {1} | 2 步（e0→dist0） | 极低：dist0 立即死路 |
| 3 | {1} | 2 步 | 极低 |
| 4 | {1,2} | 2–3 步 | **中：需走 1–2 步** |
| 5 | {1,2,3} | 2–4 步 | 中 |
| 6 | {1,2,3,4} | 2–5 步 | 中 |

**hop ≥ 4 时干扰链可以走多步**，模型必须真的走一段才能排除；
hop 2/3 时干扰链在第一步就断，极易排除。

因此难度在 **h4 处跳到新档位**，之后不再随 h 上升 —— 这正是 0.88–0.92 平台的来源。

## 影响

1. **不能用"h4–h8 平台"论证"深度能力到顶"**——续上难度并没有随 h 增长。
2. **h7/h8 的 0.88–0.92 是真实的深度外推**：模型对未训练深度
   做到了与训练深度同等的水平（h7=0.915 > h6=0.900）。
3. **h6 达不到 0.95 是任务难度，不是模型能力**：该难度档位的
   上限就是 ~0.90。

## 对判据的启示

原判据 `h6 ≥ 0.95` 隐含"训练深度应饱和"。但任务在 h4 引入的难度档
本身只有 ~0.90 的可达上限（模型侧无法再高）。

**建议改用相对判据**（已在 P04 判读中提出）：
- 主判据：`h7 ≥ 0.80` 且 `h7 ≥ h6 - 0.05`（外推不劣于训练深度）
- 辅判据：`h8 ≥ 0.75`

## 若要"难度真正随深度增长"

修改生成器，让干扰链长度**恒为 hop-2**（而非随机 1..hop-2）：

```python
L0 = hop - 2     # 固定，而非 randint(1, hop-2)
```

这样 hop 越大，干扰链越长，排除成本越高，难度随 h 单调增长。
可作为 P1-3 的候选（MVT-F）。
