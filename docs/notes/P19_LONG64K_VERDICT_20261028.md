# P19 长训（64k）判读：没有修好失败 seed；暴露 warmup 混淆与运行间方差

> 2026-10-28 15:31 判读。数据：服务器 `results/P19_long64k_s{13,17,19,53,73}.json`
> （64k 步，13:30–15:31，与 48k 基线同机同 seed 同配置，唯一差异 `--steps 64000`）。

## 一、结论（先说结果）

**P19 未达成目标。** 5 个"失败 seed"在 64k 步后只有 1 个达到 hop7 ≥ 0.80
（s53=0.805），而 48k 基线是 0/5。多训 16k 步的净收益是 **+1 个 seed**，
落在运行间方差范围内，不能作为"训练不足、可修"的证据。

## 二、同 seed 同配置的两次运行对比（关键）

因为 `--curriculum-step 8000` 让课程按绝对步数推进（与总步数无关），
且评测过程不消耗 RNG，所以 48k 基线（`remote_P04_cs48k_s53.json` 等）
与 P19 在 48000 步处**配置完全相同**。可以直接比：

| seed | 48k 基线 h6 / h7 | P19 @48k h6 / h7 | Δh7 | P19 @64k h6 / h7 | 判定 |
|---|---|---|---|---|---|
| 53 | 0.705 / 0.695 | 0.900 / 0.900 | **+0.205** | 0.805 / 0.805 | PASS（勉强） |
| 17 | 0.715 / 0.740 | 0.735 / 0.735 | −0.005 | 0.755 / 0.755 | fail |
| 13 | 0.765 / 0.765 | 0.760 / 0.760 | −0.005 | 0.740 / 0.740 | fail |
| 19 | 0.790 / 0.745 | 0.760 / 0.760 | +0.015 | 0.795 / 0.795 | fail（差 0.005） |
| 73 | 0.755 / 0.770 | 0.700 / 0.700 | −0.070 | 0.760 / 0.760 | fail |

**两个必须记录的事实：**

1. **s53 在同一配置下，48k 基线 0.695 → P19 同 step 0.900。** 这不是小抖动，
   是 +0.20 的差异。而两Run唯一的配置差异是 `--steps`，它通过
   `warm = args.steps // 50` 决定 warmup：960 vs 1280。
2. **s53 在 48k 是 0.900，训到 64k 反而降到 0.805。** 非单调——
   "多训一定更好"不成立。

## 三、归因：warmup 与总步数此前被绑死

`s71_ldm_iter4.py` 原实现 `warm = max(1, args.steps // 50)`，
即"总步数决定 warmup 长度"。因此**任何"48k vs 64k"的对比都同时改变了 warmup**，
两个因素无法分离。P19 的 s53 跳变究竟来自 warmup 还是运行间混沌，
必须用固定 `--steps 48000`、只扫 `--warmup` 的实验来判。

**已修**：新增 `--warmup` 参数（0 = 旧行为 `steps//50`），warmup 可独立设置。

**H2 实验（已启动）**：seed 53、steps 固定 48000、`--warmup {960, 1280}`，
直接复现上面那个 +0.20 的对比。若两者差 ≈0.2，则 warmup 是主因；
若两者接近，则差异来自 GPU 浮点非确定性（混沌），同样重要——
说明 hop6 收敛是随机事件。

## 四、真正的机制：hop7 由"训练集拟合度"决定，不是由外推手段决定

把 13 个 48k 基线的**最终 train task loss** 与 hop7 排在一起，出现清晰单调关系：

| 组 | task loss | hop7 | 判定 |
|---|---|---|---|
| s67 | 0.0006 | 0.835 | PASS |
| s79 | 0.0027 | 0.825 | PASS |
| s29 | 0.0019 | 0.805 | PASS |
| s11 | 0.0528 | 0.840 | PASS |
| s89 | 0.0707 | 0.900 | PASS |
| s71 | 0.1348 | 0.915 | PASS |
| s83 | 0.1733 | 0.905 | PASS |
| s61 | 0.2392 | 0.895 | PASS |
| s73 | 0.2507 | 0.770 | fail |
| s13 | 0.2267 | 0.765 | fail |
| s53 | 0.2102 | 0.695 | fail |
| s19 | 0.3970 | 0.745 | fail |
| s17 | 0.4134 | 0.740 | fail |

**task loss < 0.15 的 8 个 seed 全部 PASS；≥ 0.21 的 5 个全部 fail。**
P19 的 s53 把 task loss 从 0.2102 压到 0.0031，hop7 随之从 0.695 升到 0.805——
与上表完全一致。

**两个推论：**

1. **"失败 seed"= 训练集没拟合上**，不是"外推能力不足"。它们的任务损失停在
   0.21–0.41（即还有 20–40% 的训练样本是错的），这属于优化停滞，不是容量或
   架构问题（同参数下另外 8 个 seed 拟合上了）。
2. **训练集拟合度的天花板 ≈ 0.80–0.84。** 拟合到 0.0006–0.0031 的三个 seed
   （s67/s79/s29）hop7 也只有 0.835/0.825/0.805。**把训练集背下来并不会带来
   更强的 hop7 外推。** 这与"外推只靠训练覆盖"的既有结论一致，并且给出了
   定量的上界。

因此 P19 的问题应改述为：**为什么有的 seed 会优化停滞（task loss 卡在 0.2+），
有的能收敛到 0.003？** 这是初始化/优化动力学问题，可通过重复跑同一 seed、
比较收敛与停滞两组的早期轨迹来研究。

## 五、对既有结论的影响

`P0_FINAL_VERDICT_20261028.md` 的"8/13 = 61.5% 通过率"必须加一条限定：
**同一配置重跑同一 seed，h7 的波动可达 ±0.10，个别 seed 达 +0.20。**
因此：

- "配方可靠（≥50% seed 通过）"这个判据**形式上仍通过**，但 61.5% 这个点估计
  的不确定度很大；按 n=13、p≈0.6 的二项标准误约 ±0.135，
  95% 区间约 [0.36, 0.80]，与 50% 门槛几乎不可区分。
- 更稳妥的表述是"**hop6 收敛是概率约 0.6 的随机事件**，而非确定性结果"。
- **任何单 seed 的绝对分数都不能作为配方优劣的证据**；后续所有配方对比
  必须多 seed（≥3）并报告均值与跨度。
