# AMD 实例第一批结果：warmup=1280 把通过率从 1/6 提到 4/6

> 2026-10-29 20:30。数据：`results/amd/MAIN_w1280_s{13,17,19,53,71,73}.json`
> （DSW-AMD，ROCm 7.2.3，torch 2.12，48k 步，`--warmup 1280`）。
> 对照基线：`results/remote_P0{4,5}_cs48k_s*.json`（3080，warmup 960）。

## 一、结果

| seed | task loss | hop6 | **hop7** | hop8 | r8 | 判定 | 基线 hop7 | Δ |
|---|---|---|---|---|---|---|---|---|
| 13 | 0.1036 | 0.900 | **0.890** | 0.890 | 0.937 | **PASS** | 0.765 | **+0.125** |
| 17 | 0.3819 | 0.760 | **0.810** | 0.775 | 0.832 | **PASS** | 0.740 | **+0.070** |
| 19 | 0.3623 | 0.750 | 0.725 | 0.695 | 0.823 | fail | 0.745 | −0.020 |
| 53 | 0.1374 | 0.885 | **0.915** | 0.880 | 0.920 | **PASS** | 0.695 | **+0.220** |
| 71 | 0.2214 | 0.860 | **0.830** | 0.795 | 0.920 | **PASS** | 0.915 | −0.085 |
| 73 | 0.2723 | 0.780 | 0.765 | 0.770 | 0.852 | fail | 0.770 | −0.005 |

**通过率 4/6 = 66.7%**（基线同 6 seed 为 1/6 = 16.7%）。

## 二、结论

**warmup=1280 是把"失败 seed"救回来的低成本手段**，与 H2 的双 GPU 结论一致：
s53 的 hop7 提升 **+0.220**，s13 **+0.125**，s17 **+0.070**。

但它**不是单向的**：s71 下降 0.085，s19 下降 0.020，s73 下降 0.005。
即 warmup 变长**提高收敛概率，不保证每个 seed 都变好**——
这与 H-029 的结论一致（warmup=1280 的两次运行 task loss 相差 36 倍）。

### 与 H-029「task loss 决定成败」的对应

| seed | task loss | hop7 | 是否符合"task<0.15→达标" |
|---|---|---|---|
| 53 | 0.1374 | 0.915 | ✓ |
| 13 | 0.1036 | 0.890 | ✓ |
| 71 | 0.2214 | 0.830 | ✗（task 偏高但达标） |
| 17 | 0.3819 | 0.810 | ✗（task 很高但达标） |
| 73 | 0.2723 | 0.765 | ✓（task 偏高但未达标） |
| 19 | 0.3623 | 0.725 | ✓（task 偏高未达标） |

**这条规则在 warmup=1280 下不再干净**：s17（task 0.38）达标而 s53 之外的
s71（task 0.22）也达标，说明"task loss < 0.15"是**充分不必要**条件，
且阈值随 warmup 变化。原先那条单调关系是在 warmup=960 这一档上建立的，
换档后必须重新标定。

## 三、跨硬件一致性（seed 17 逐点对照，AMD vs 3080 基线）

| step | cap | AMD task / r8 / h6 | 3080 task / r8 / h6 |
|---|---|---|---|
| 4000 | 2 | 0.685 / 0.460 / 0.435 | 0.687 / 0.463 / 0.420 |
| 8000 | 3 | 1.242 / 0.585 / 0.510 | 0.652 / 0.614 / 0.495 |
| 12000 | 3 | 0.221 / 0.708 / 0.525 | 0.186 / 0.716 / 0.565 |
| 16000 | 4 | 0.408 / 0.775 / 0.655 | 0.368 / 0.711 / 0.525 |

形态同构，包括"升档时 task loss 反弹"（3080：0.186→0.368；AMD：0.221→0.408）。
逐点差值 task ≤0.09、r8 ≤0.07、h6 ≤0.13。

**结论：ROCm 迁移正确，训练行为与 CUDA 基线同构。**
但注意两跑 warmup 不同（1280 vs 960），所以这不是严格的同配置复现——
严格复现需在 910B 上用 `--warmup 960` 跑同一 seed 再比。
