# 实验设计缺陷：`--steps` 同时控制课程调度，48k vs 24k 不可直接对比

> 2026-10-27 20:20 发现。

## 问题

`s71_ldm_iter4.py` 中课程阶段的划分依赖总步数：

```python
for step in range(start_step, args.steps + 1):
    _si = min(len(stages) - 1, step * len(stages) // max(1, args.steps))
    cap = stages[_si]
```

`--steps 48000` 时，hop 从 2 升到 6 需要 48000 步；
`--steps 24000` 时只需 24000 步。

**同样在 step=24000 处**：
- 24k run：课程已走完全程（cap=6）
- 48k run：课程只走到一半（cap≈4）

因此 48k run 在 24000 步时面对的是更简单的数据分布，表现更低是**正常的**，
不能说明"48k 训练更差"。

## 实测证据

| run | seed | 配置 | 24k 处 hop7 |
|---|---|---|---|
| P02_loop_s71 | 71 | steps=24000 | **0.875** |
| P03_long_s71 | 71 | steps=48000 | **0.560** |

配置完全相同（ouro、step_sup、bs=64、lr=1e-3、curriculum 2-6、同数据），
唯一差别是 `--steps`。24k 处 hop7 差 0.315，原因是课程进度不同。

## 影响

1. **P0-3 的"48k 更长所以更好"结论不成立**：
   P03 的 48k 终值（hop7=0.925）不能直接与 P0-2 的 24k 终值（0.875）比较，
   因为两者的课程节奏不同。
2. **但 P0-3 内部对比仍有效**：
   同一 run 从 24k 到 48k 的提升（0.560 → 0.925）说明了"继续训练有用"，
   尽管课程也在同步推进。
3. **P0-1b（48k 重跑 6 seed）的判据需要重新考虑**：
   它测的是"48k + 更缓慢的课程"，与 P0-1（24k + 快速课程）是两个变量同时变。

## 修法（下一次实验）

课程应按**绝对步数**固定，与总步数解耦：

```python
CAP_SCHEDULE = {0: 2, 8000: 3, 16000: 4, 24000: 5, 32000: 6}
def cap_at(step):
    return max(v for k, v in CAP_SCHEDULE.items() if step >= k)
```

这样 24k 和 48k 在相同 step 处面对相同难度，可公平对比。

## 当前处理的取舍

**不中断 P0-1b**（6 个 48k run 已在跑，20:07 启动）。
它的结果仍有价值：回答"48k + 该课程节奏下，6 个 seed 能否达标"。
但**不能**用它论证"48k 优于 24k"——那是 P0-3 的问题，而 P0-3 的对比已被证明不严谨。
