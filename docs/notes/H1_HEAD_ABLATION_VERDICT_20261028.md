## 三、逐臂解释

### mlp：+37,249 参数换来 hop6 从 0.80 到 0.97

把 `Linear(192→1)` 换成 `192→192→GELU→1`，hop6 +0.17、hop7 +0.095，
且 hop2–5 全部 ≥0.99（无跷跷板）。task loss 从 0.2931 降到 0.0054——
**训练分布从"没拟合上"变成"拟合上了"**，与 H-027 的判据
（task loss < 0.15 才可能达标）完全一致。

含义：那个占全模型 0.013% 的读出层，此前**确实是瓶颈**。
它只读候选 token 自己的隐状态，逼着共享 core 把"答案在哪"压进单个向量；
给一个两层 MLP 就能让 core 少背这个负担。

### bilinear：拟合了训练集，但外推崩了

task loss 0.0035、r8 = 0.995（训练分布完美），但 hop6 只有 0.735、
hop7 只有 0.51。**r1 = 0.519（随机）而 r8 = 0.995** —— 它学会了
"必须用多轮"，却把轮次用在了记忆训练分布上，而非可迁移的追踪。
这是"背下训练集不带来外推"（H-027 §推论）的又一个实例，
且比 mlp 更极端。

### xattn：完全学不动

task loss = **0.6932 = ln2**，48k 步后所有指标仍精确停在随机水平
（dev_r* 0.499–0.509）。让读出端对全序列做注意力**彻底破坏学习**，
与 dense 基线停在 ln2 是同一类失败。

可能原因（未验证）：候选作 query 的注意力在早期把梯度引向无信息位置；
softmax 归一化稀释了有效梯度；111K 新增参数在零初始化 core 旁边
形成了坏的优化起点。**这是本项目第二个"给读出端更多自由度反而更差"的
实例**（第一个是 H-025 邻接掩码）。

## 五、必须补的验证（单 seed 不足以定论）

本批只有 seed 17。已知运行间噪声 ±0.10，而"证实"档要求 h7 ≥ 0.80，
seed 17 的 linear 对照本身就有 0.78（距阈值 0.02）。因此：

1. **扩 seed 到 ≥3**（建议 s71 通过型 + s53/s13 失败型），
   每臂 48k，判据改为"≥2/3 的 seed 上 mlp 的 h7 高于同批 linear 对照 ≥0.05"。
2. **中间容量扫描**：mlp 用了 37K 新增参数。需区分"容量"与"非线性"：
   加一个 `Linear(192→384)→Linear(384→1)`（同等参数量、无非线性）
   或 `192→64→1`（更小），看效应量随容量如何变。
3. **与 Ouro 损失的交互**：mlp 臂的 r1 = 0.884，比 linear 的 0.749 高。
   需确认 mlp 不是靠"让单轮更能打"取胜（若是，则它削弱而非加强了
   循环的必要性）。**这一点直接影响论文的核心论据，见下节。**

## 六、附带发现：r=1 在 Ouro 配方下不再是随机（影响核心论据）

H-024 记录的"循环被真实使用"依赖 **r=1 恒为随机**（persist 监督下
三 seed 0.494–0.508）。但该结论**只对 persist-sup 成立**。

在当前标准配方（Ouro + step-sup）下，13 个 48k 基线的 r1 为
**0.399–0.874，均值 ≈ 0.71**；P19 的 5 个 seed 为 0.701–0.846。
只有 s83（0.413）与 s11（0.399）接近随机。

原因：persist-sup 只从第 R 轮起监督，早期轮次无梯度 → 保持随机；
Ouro 用均匀先验，**每一轮都拿梯度**，第 1 轮因此变得可用。

**影响**：论文不能再写"r=1 恒随机，故循环被用于计算"。可写的替代口径是
**轮次增益**：r1 ≈ 0.71 → r2 ≈ 0.90 → r8 ≈ 0.93，即 7 个额外轮次共贡献
约 +0.22，且绝大部分（+0.19）在第 2 轮就拿到。这与"r≈2 饱和"
（arXiv:2610.26030 "two loops optimal"）一致，但论据要从
"单轮不可能"改为"单轮显著更差、增益在 r=2 饱和"。

此项需在论文骨架 v4 中修正，见 `PAPER_SKELETON_20261027.md` 的口径段。
