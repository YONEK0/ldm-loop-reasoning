# H2 判读：warmup 长度被证实是 s53 成败的原因（双 GPU 各自复现）

> 2026-10-28 18:25 判读。数据：`results/warmup/H2_w{960,1280}_s53.json`
> （本机 RTX 5060，seed 53，**steps 固定 48000**，唯一变量 `--warmup`）。

## 一、结论

**P19 的 s53 跳变不是"64k 步"的功劳，是 warmup 从 960 变成 1280 的功劳。**

同 seed、同步数、同配置，只改 warmup：

| warmup | task loss | hop6 | hop7 | hop8 | 判定 |
|---|---|---|---|---|---|
| 960 | 0.2121 | 0.750 | 0.795 | 0.710 | fail |
| 1280 | 0.1079 | **0.915** | **0.890** | 0.845 | **PASS** |

## 二、双 GPU 交叉复现（关键）

这四个 run 覆盖两块不同的卡，warmup 两个水平各出现两次：

| run | GPU | warmup | task loss | hop6 | hop7 | 判定 |
|---|---|---|---|---|---|---|
| 48k 基线 | 3080 | 960 | 0.2102 | 0.705 | 0.695 | fail |
| H2_w960 | 5060 | 960 | 0.2121 | 0.750 | 0.795 | fail |
| P19 @48k | 3080 | 1280 | 0.0031 | 0.995 | 0.805 | **PASS** |
| H2_w1280 | 5060 | 1280 | 0.1079 | 0.915 | 0.890 | **PASS** |

**warmup=960 的两次独立运行全部 fail；warmup=1280 的两次全部 PASS。**
跨两块不同架构的 GPU 一致，且 task loss 同向变化（0.21 → 0.003–0.108）。

## 三、为什么会混淆（设计缺陷复盘）

`s71_ldm_iter4.py` 原实现 `warm = max(1, args.steps // 50)`，
即**总步数决定 warmup 长度**。于是任何"48k vs 64k"的对比都同时改了两个因素：

- `--steps 48000` → warmup 960
- `--steps 64000` → warmup 1280

P19 的本意是测"多训 16k 步能否救回失败 seed"，实际测的是
"warmup 长 320 步能否救回失败 seed"。我在 P19 判读时发现 s53 在 48k 处
就从 0.695 跳到 0.900、训到 64k 反而降到 0.805（非单调），据此定位到
warmup 是唯一配置差异，随后做了 H2 把两者彻底分离。

**已修**：新增 `--warmup` 参数（0 = 旧行为 `steps//50`），warmup 可独立设置。

> 这是本项目第二次踩"`--steps` 同时控制两件事"的坑。
> 第一次是 `--steps` 同时控制课程节奏（已加 `--curriculum-step` 修复，
> 见 `docs/notes/ISSUE_steps_couples_curriculum.md`）。
> **教训应写入论文的方法学章节：任何"训练预算"类参数都不能隐式绑定
> 其他超参，否则预算对比无法归因。**

## 四、对 H-029 的意义

H-029（优化停滞）的**成因已被定位到 warmup**：

- task loss < 0.15 → 达标；≥ 0.21 → 不达标（13 seed 的单调关系）
- warmup 960 让 s53 的 task loss 停在 0.21（停滞）；1280 让它降到 0.108
- 停滞不是容量/架构问题（同参数同配置下另一组 warmup 就拟合上了）

但**尚未证明 warmup 是唯一杠杆**：两次 w=1280 的 task loss 相差 36 倍
（0.0031 vs 0.1079），hop6 相差 0.08。说明 warmup=1280 只是**提高收敛概率**，
不是保证。

## 五、下一步（服务器已停，全部在本机 5060 跑）

1. **把 warmup=1280 应用到其余 4 个失败 seed**（17/13/19/73），各 48k。
   若多数转为达标，则"配方可靠"这个说法才真正成立，且修复成本是一行参数。
2. **反向检查**：在已通过的 seed（71/89/83…）上试 warmup=1280，
   确认不会把本来通过的弄坏。若 warmup 加长有系统性收益，
   标准配方应改为 `--warmup 1280`（或按 steps 的固定比例重新标定）。
3. **warmup 扫描**：960 / 1280 / 1920 / 2560 × seed 53，看是否存在
   明确的转折点，还是连续的概率平移。这决定"配方"该怎么写。
4. **与 H-028 合并验证**：mlp 读出臂（seed 17）是在 warmup=960 下
   达到 h6=0.97 的。需确认 mlp 的收益在 warmup=1280 下仍然存在
   （可能是同一因素的两条路径，也可能是独立叠加）。

## 六、对论文的影响

- P0 判读的"8/13 = 61.5%"应补一句：**该通过率是在 warmup=960 下测得的**，
  换 warmup=1280 后可能显著提高（已在 1 个 seed 上复现两次）。
- "配方可靠"目前**只能说是弱成立**：它依赖一个此前未被识别的超参，
  且跨 seed 的一致性未测。
