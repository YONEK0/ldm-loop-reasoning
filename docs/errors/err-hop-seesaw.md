# E-001 相邻 hop 跷跷板（精度交替崩溃）

**状态：已解决（2026-10-26）**

## 症状

训练 loss 正常下降（0.0–0.26），但 eval 时某个 hop 的精度反复从 ~0.9 崩到 ~0.0，
且相邻 hop 此消彼长。典型轨迹（服务器基线，exact-T）：

```
step  6000:  hop2=0.035  hop3=0.98       ← hop2 归零
step 18000:  hop3=0.015  hop5=0.955      ← hop3 归零
step 20000:  hop3=0.0    hop6=0.895      ← hop3 归零，hop6 上来
step 22000:  hop2=0.995  hop3=0.46       ← hop2 回来，hop3 半崩
```

## 复现

```bash
python s71_ldm_iter4.py --steps 24000 --pos none --seed 17 \
  --curriculum 2,3,4,5,6 --eval-every 2000 --out results/repro.json
```
（不加 --persist-sup）

## 根因

**训练/评测分布错配**：exact-T 只在第 R 轮监督（hop_k 的样本只算第 k−1 轮的损失），
模型从未见过"算完之后继续跑"的状态。评测要跑 1–8 轮，多出的轮次在训练分布外，
一过冲就毁答案。

证据：train loss 全程正常但 eval 剧烈震荡——若是优化问题，loss 也会异常。

## 排查过程中被排除的方向（都有实验证据）

| 方向 | 结论 | 证据 |
|---|---|---|
| 残差爆炸 | 证伪 | 成功/失败残差增长 6.78× vs 6.63× |
| 学习率过高 | 证伪 | 1e-3/5e-4/3e-4 全失败 |
| 参数漂移（EMA） | 证伪 | 救 s53 毁 s17，净效果为零 |
| 容量不足（加宽） | 证伪 | 参数 ×3.9，峰值 0.669 vs 0.671 |
| 课程硬切换 | 证伪 | mix 0/0.3/0.6 峰值全在 0.664–0.671 |
| 读出层共享 | 弱支持 | per-hop 头 +0.089，但不根治 |

## 修法（已验证）

```bash
--persist-sup    # 第 R 轮起每轮都要答对；t<R 轮次用 0.3 权重轻压
```

**效果**：归零事件 5 → 0；3/6 seed 五级全解（1.000/0.999/0.993）。
