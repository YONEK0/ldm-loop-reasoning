# H-028（待验证）：决策模块的 193 参数线性读出是 hop6 收敛的瓶颈之一

> 2026-10-28 提出。预注册判据见 `docs/plans/PREREG_HEAD_ABLATION_20261028.md`
> （跑前写定，阈值 0.85 / 0.05 不可事后调整）。

## 假说

当前决策模块为 `gather_pos(h, cand_pos) → Linear(192,1) → softmax`，共 **193 个
参数，占全模型 0.013%**。它只读候选 token 自己的隐状态，**不与全序列交互、
不比较候选内容**，等于逼着共享 core 把"答案在哪"的全部信息压进候选位那一个
向量里。给它更强的读出能力（容量 / 双线性比较 / 自己检索序列）应能提高 hop6
收敛率。

## 为什么以前没测

- 唯一的旧实验是 **H-009 per-round 独立读出头**（每轮一个 score 层），
  峰值 0.671→0.760。但那次跑在 **MVT-5** 上——该任务有"选更长的候选"捷径，
  在全部 19750 个样本上正确率 1.0000（H-023），**结论不可用**。
- `step_head` / `exit_mlp` / `proc_head` 是辅助监督头，不属于决策模块。
- `n_coda` 恒为 1，从未做消融；也没有"去掉 Coda 直读 core 状态"的对照。

## 四臂（单变量：只换 `--head-type`，其余与 13 seed 基线完全一致）

| 臂 | head_type | 打分形式 | 增量参数 | 总参数 |
|---|---|---|---|---|
| A | linear | `Linear(192→1)` 读候选隐状态（现状/对照） | 0 | 1,474,307 |
| B | bilinear | `(W·h_cand) ⊙ e_cand` 求和，与候选输入表示比较 | +36,864 | 1,511,171 |
| C | mlp | `192→192→GELU→1` | +37,249 | 1,511,556 |
| D | xattn | 候选作 query 对全序列单头注意力后打分 | +111,361 | 1,585,668 |

配置：seed 17（48k 基线的失败种子，h6=0.715 / h7=0.740），48k 步，
`--curriculum-step 8000`、`--ouro --step-sup`、`--lr 1e-3`、`--r-max 8`。

## 判据（预注册）

| 结果 | 判定 |
|---|---|
| 任一非 A 臂 h6 ≥ 0.85 且 h7 ≥ 0.80 | **证实**：决策模块承重，读出侧是瓶颈之一 |
| 非 A 臂相对 A 提升 0.05 ≤ Δh6 < 0.12 | **部分承重**：记录效应量，扩 seed（17/53/13）复验 |
| 四臂 h6 全在 A 的 ±0.05 内 | **证伪**：轻量决策模块足够，瓶颈在 core 轮次状态 |

附加防跷跷板判据：某臂 h6 上升但 hop4/hop5 下降 >0.05 → 记为未通过。
