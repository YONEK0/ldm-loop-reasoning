## 1. P0：不做完不能启动真实训练

### P0-1 Ouro 配方的 seed 稳定性

**为什么**：现在只有 2/2，样本太小。整个后续训练依赖这个配方。

**实验**：`MVTD3_ouro_s{S}`，S ∈ {11, 13, 19, 29, 37, 43}（6 个新 seed）
- 任务 MVT-D v2，课程 2–6，24k 步，`--ouro --step-sup`，bs=64，lr=1e-3

**判定（预注册，二选一）**：
- **通过**：≥5/8 总 seed（含已有 s71/s17）满足 `dev_r6 ≥ 0.95` 且 `hop7 ≥ 0.80`
- **不通过**：<5/8 → 配方不可靠，必须先定位方差来源（见 P2-1）

**若通过**：配方可用于真实训练。

### P0-2 参数效率重做（H-003 已作废）

**为什么**："循环优于同等参数稠密"是核心卖点，现在**零干净证据**。

**实验**：MVT-D v2，Ouro 损失，24k 步，3 seed（71/17/53）
- loop L=1（1.47M 参数）
- dense mid=1（1.40M）
- dense mid=3（2.29M）
- dense mid=5（3.18M）

**判定**：
- **通过**：loop 的 hop6 均值 ≥ dense 最好臂 + 0.10，且 loop 的 hop7 ≥ 0.70
- **部分**：loop 优于同参（mid=1）但不优于 2.3× 参数臂
- **不通过**：loop ≤ dense 任一臂

**注意**：若 P0-1 未通过，本项用 persist 配方跑，仍然有效（比较的是架构）。

### P0-3 训练长度确认

**为什么**：persist 的 s17 到 24k 时 r=2 还在涨（0.524→0.852），
Ouro 的 s17 到 24k 也刚过 0.85。**可能所有结论都建立在训练不足上。**

**实验**：Ouro，s71 + s17，48k 步（对比已有 24k）
- eval_every=4000

**判定**：
- **已收敛**：48k 相对 24k 的 `dev_r8` 提升 < 0.02 → 24k 足够
- **未收敛**：提升 ≥ 0.02 → 后续所有实验改用 48k

## 2. P1：支撑论文（可与真实训练并行）

### P1-1 Ouro 第二阶段（冻结主体，只训 gate）

- 从 P0-1 的最佳 ckpt 出发，冻结 backbone，只训 exit_mlp
- 目标：让 r 自适应（难样本多跑几轮）
- 判定：硬退出 `mean_rounds ≤ 3.5` 且精度损失 ≤ 2pp

### P1-2 邻接掩码任务（检验"每轮一跳"）

**为什么**：MVT-D v2 在 r=2 就饱和，**根本检验不了串行深度**。
必须让每轮只能沿边传播一跳（Chen 2026 做法）。

**实现**：在注意力上加邻接掩码，使第 t 轮的信息只能从距离 ≤ t 的节点流入。

**判定**：
- **阶梯成立**：hop h 的最优 r 满足 r*(h) ≈ h，且单调递增
- **不成立**：r 扫描平坦

### P1-3 更深外推（hop9/10）

- 训练课程 2–8，测 hop9/10
- 沿用 P0-1 的配方

## 4. 昇腾 910B 迁移要求（写进代码，不等到迁移时再改）

- 所有 device 选择用 `torch.cuda.is_available()`（torch_npu 会接管）
- `torch.cuda.get_rng_state/set_rng_state` 需在 NPU 上改为 `torch_npu.npu.*`

### 迁移检查清单
1. `torch_npu` 安装 + `import torch_npu`
2. RNG state 保存/恢复分支（续跑用）
3. `attention` 实现：确认 `scaled_dot_product_attention` 在 NPU 上的可用性
4. 融合编码的 `index_add`/`sum` 在 NPU 上的数值一致性

用 `MVTD2_s71` 的配置在 910B 上跑 4k 步，对比 loss 轨迹与
`dev_r1/dev_r2` 数值，**偏差 < 0.02 才算迁移成功**。
