- **适用范围**：HybridLoop/LDM 双线全部脚本、实验、交接与自动化流程

## 1. 授权分级（先授权后执行，不越权）

| 级别 | 内容 | 生效方式 |
|---|---|---|
| L1 已授 | 验证期任务（阶段 1 计划内）+ 跑完释放实例 | 当前有效 |
| L2 需授 | 任何重训/长程训练（>2h GPU）、新数据集生成、改冻结契约 | 用户明示 |
| L3 需授 | 关机后重开实例、租新实例、魔搭新建/转公开仓库 | 用户明示 |
| 禁止 | 训练集/确认集事后改动；改已冻结判据；未预注册先跑关键实验 | 任何情况下 |

## 2. 预注册纪律（防事后解释）

1. 关键实验的**判读规则必须先写入战役日志（§编号）再启动运行**——脚本、阈值、通过/部分/失败三档一次写死。
2. 跑完不得修改判读；结果不达判据即如实记阴性，不得改判据重跑。迭代需要新设计 → 新 § 编号 + 新确认集（旧集标记消耗）。
3. 决策点（如 D1）分支表在实验前预写，读数后只填分支不写新分支。

## 3. 数据纪律

1. 数据集一经 `--write` 冻结（manifest 含 sha256），实验只读；改动=新版本号+新目录（v2/v3 先例）。
2. 确认集（confirm_*）单次评估原则：只在配方与阈值冻结后评一次；其结果触发任何设计改变 → 重新生成确认集。
3. 捷径审计前置：新任务必须先过"标签捷径/位置偏置/统计可推"三查（教训：v1 单步捷径 68.9%、存活位统计捷径 r4=0.14）。
4. 深度必要性检查（新增，教训 §12.5）：任务设计必须先验证"单遍并行可解性"——单轮能解的任务不上循环。

## 4. 证据分级（日志与报告统一标注）

【实测】服务器/本机跑出的数字；【代码确认】读代码可证的性质；【强推断】有文献+数据双重支撑但未直接测；【未确认】假设。阴性结论必须写明排除范围（预算、规模、任务族边界）。

## 5. 服务器生命周期（每实例执行，缺一不可）

```
租用 → 环境验证（torch 版本 + GPU 型号 + overfit 三组 loss=0）
     → 部署（魔搭取包，sha256 校验一致才继续）
     → 任务（nohup 后台 + 服务器侧 watcher 自动落盘；终端可断）
     → 取回（结果 base64/打包回本地，哈希核对）
     → 归档（日志 §N + results/ 落位）
     → shutdown → 平台释放
```

异常处置先例（沿用）：下载卡死→aria2 16 线程续传；OOM→expandable_segments+断点续跑；孤儿进程→按真 PID kill；SSH 通道超时→重连查 ps（后台进程通常健在）。

## 6. 存储与安全（执行 STORAGE_CONTRACT）

1. C 盘零权重/数据集落盘（junction 与 HF_HOME 已就位；新终端自动生效）。
2. 服务器大文件只落 `/root/autodl-tmp`；中转一律走魔搭私有库（`Yoneko/ldm-feasibility-testkit` 等），上传带 sha256 与 commit message。
3. **凭据纪律**：SSH 密码/魔搭 token 只存在于本机 `ssh_server.py` 与会话中；**任何带凭据的文件不得进魔搭、git、日志归档**；token 定期轮换（当前 token 已多次出现在命令行，阶段末轮换）。
4. 打包内容白名单制：只有 sNN 脚本、数据集、README 入 bundle；`ssh_server.py`、`_tmp_*`、本地 results 永不入包。

## 7. 归档纪律

1. 战役日志 append-only（LDM_CAMPAIGN_LOG / S08_CAMPAIGN_LOG），每批次一个 §，含：配置、判读、产物路径、排除范围。
2. 结果三副本原则：服务器盘（关机保留）+ 本地 `results/` + （关键批次）魔搭 bundle。
3. 永久存档点（转折处 ckpt，映射原始 goal）：触发条件见阶段计划 §3.3；存档命名 `ckpt_perm_<milestone>_<step>.pt`，同配方 manifest 一并冻结。

## 8. 报告纪律

1. 阴性如实报，带 CI 与排除范围；区分"未通过"与"未测"。
2. 不用"应该是/大概"覆盖可实测项；可实测未测 → 标【未确认】。
3. 每阶段末给用户一份读数报告（判据→分支→去向），语言与日志一致。
