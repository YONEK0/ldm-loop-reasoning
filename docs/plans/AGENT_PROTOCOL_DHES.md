## 2. 当前已验证的配方（基线，不要退回旧配方）

```bash
/root/miniconda3/bin/python s71_ldm_iter4.py \
  --pos none --persist-sup --step-sup \
  --curriculum 2,3,4,5,6 --steps 24000 --bs 64 --lr 1e-3 \
  --r-max 8 --seed <S> --early-stop --eval-every 2000 \
  --out results/R_<name>.json
```

**已知成绩**（8 个种子，24k 步）：
- 五级全解（hop2–6 全部 ≥0.95）：7/8（s17=0.999, s41=0.993, s53=1.000,
  s31=0.996, s71=1.000, s23=0.989；只有 s89=0.802 失败）
- 稠密对照（dense mid=1 / mid=3，同配方）：hop5/6 停在 0.485–0.59 = 随机
- 配置常量：d=192, heads=4, ffn=768, n_rounds=8, 参数量 1.47M（含 step_head 61,760）

**已被证伪的方向，不要重试**：
- 加宽模型（d=384，参数 ×3.9）→ 峰值 0.669 vs 基线 0.671，无效
- 课程平滑混合（mix 0.3/0.6）→ 0.664–0.671，无效
- 课程回采（cap-reach=2）→ 四个失败种子峰值 0.763–0.808，无效
- 学习率扫描（5e-4 / 3e-4）→ 全失败，3e-4 最差
- 权重 EMA（0.99）→ 救一个种子毁一个，净效果为零
- 残差爆炸（文献假说）→ 成功/失败残差增长 6.78× vs 6.63×，无区分度
- per-hop 独立读出头 / FiLM 轮次调制 → +0.089 / +0.03，但破坏参数效率叙事，
  且组合后反而更差（0.812 vs 0.999）

详细记录见 `docs/errors/INDEX.md` 与 `docs/hypotheses/INDEX.md`。

## 3. 实验队列（按优先级，做完一项再做下一项）

### Q1. hop7/8 外推（最高优先，科学价值最大）
**问题**：训练课程只到 hop6，模型能否解 hop7/8？历史上恒为 0.5（随机）。
**做法**：用基线配方跑 2 个种子（17、53），**不改课程**，跑完后看 `confirm_*` 指标
（评测自动包含 confirm_depth.jsonl = hop7/8 外推集）。
**判读**：`confirm_r8` 与 `confirm_r6_by_hop` 里 hop7/8 的值。
- ≥0.8：外推成立 → 重大正面结果
- 0.5 左右：外推仍失败 → 记录为负面结论

### Q2. 成功率做实（补种子）
**问题**：当前 7/8 = 87.5%，但样本太少（置信区间宽）。
**做法**：补 4 个新种子（201, 202, 203, 204），同基线配方。
**判读**：统计五级全解数 / 总数；报告 95% 置信区间（Wilson）。

### Q3. s89 失败个案
**问题**：唯一失败的种子，hop5 卡 0.455。
**做法**：s89 跑 3 个变体各一次：
  (a) `--step-weight 1.0`（加大路径监督权重）
  (b) `--steps 36000 --curriculum 2,3,4,5,6,6,6`（延长 hop5/6 阶段）
  (c) `--seed 189`（近邻种子，确认是否种子特异）
**判读**：任一配置达 5/5 → 说明是权重/预算问题；全失败 → 记录为"初始化敏感"。

### Q4. 参数效率正式对照（论文需要）
**问题**：需要"loop 1.47M 解出 hop5/6，dense 更多参数解不出"的正式数字。
**做法**：跑 dense mid=1（同参 1.4M）、dense mid=3（约 2.4M）、dense mid=5（约 3.4M），
同基线配方（含 --persist-sup --step-sup），各 2 个种子。
**判读**：三档 dense 的 hop5/6 若全部 <0.7，则参数效率结论成立。

### Q5. 消融：路径监督的贡献（论文需要）
**做法**：在 s17、s71 上跑 2×2 消融：
  - persist-sup only（无 step-sup）
  - persist-sup + step-sup
  （另两格已在历史数据里：无 persist-sup 无 step-sup = 基线 exact-T；
   无 persist-sup + step-sup = 未跑，可补）
**判读**：给出"两个改动各自的贡献"表格。

## 4. 预注册判读标准（不许改）

| 指标 | 达标阈值 | 说明 |
|---|---|---|
| 五级全解 | dev_r8 by_hop 中 hop2–6 **全部 ≥0.95** | 主判据 |
| 收敛 | 峰值出现在 ≤24k 步内 | 超预算视为未收敛 |
| 参数效率 | loop 达 5/5 且 dense 同预算 <0.7 | 对照判据 |
| 外推 | confirm hop7/8 ≥0.8 | Q1 专用 |
| 稳定性 | 同配置 ≥2 种子一致达标 | 防单点侥幸 |

**禁止**：看到部分达标就宣称成功；用"峰值出现在某个中间步"当达标（必须用
`early_stop` 或最终 eval 的口径）。

## 5. 记录义务（每批实验后必须做）

## 6. token 预算纪律

- 每次 dsh 调用只读**摘要**，不要 cat 整个 json（用 `s78_agent_loop.py summarize`）
- 单次调用的输入控制在 2000 token 以内（摘要 + 协议要点）
- 每 10 分钟最多 1 次调用；一批实验（约 1 小时）最多 2 次调用
- 整夜总调用上限 **30 次**，到上限后停止并写报告

## 7. 出问题时

| 情况 | 动作 |
|---|---|
| 训练进程死了但未完成 | 用 `--resume` 重启（`_state.pt` 存在）；若是 OOM 减 bs 到 32 |
| loss 出现 NaN/inf | 记录到错误档案，降 lr 一半重跑一次；仍 NaN 则放弃该配置 |
| 多个 hop 同时归零（灾变） | 回滚到最近的 `_MILESTONE_*.pt`；查是否违反配方 |
| 显存不足 | 减少并行到 1 个 |
| 结果与预注册不符 | **照实记录**，不许改判据或改口径 |
| 服务器即将到期（<1 小时） | 停止新实验，把所有 `results/*.json` 和 `docs/` 打包，写最终报告 |
