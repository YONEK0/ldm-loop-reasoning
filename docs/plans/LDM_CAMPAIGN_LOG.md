## §1 契约冻结（2026-10-23，用户逐项确认）

| 契约 | 确认值 |
|---|---|
| 任务域 | T-13 合成关系图改造为"选择正确的下一步边动作" |
| 输出 | 候选逐项 logit，softmax 交叉熵监督唯一正确动作 |
| 首轮范围 | 机制可行性：固定 1 轮 / 固定多轮 / 自适应退出 + 同参数稠密从头诊断臂；不发参数效率结论 |
| 规模与退出 | ~2M 参数级（d=192、1+2+1 块、R∈[1,6]，待 sizing 校准）；固定深度质量 warm-up → 可微样本级退出 → λ 退火 |

次级默认接受：质量容差讨论起点 2 个百分点；KL/熵仅作诊断不作硬停止；确认集单次评估，迭代后须换新确认集。

**关键设计发现（代码级推导，写入规格 §3.1）**：T-13 函数式图（每实体每关系至多一条出边）上做"选下一条边"，正确动作由 goal[0] 关系名唯一决定，无需多跳追踪——任务退化。因此 LDM 任务用**非函数式图**：e0 有多条同关系候选边，唯一一条能走通完整目标路径；竞争边在不同深度断链。

## §2 数据集 v1 冻结（s62_ldm_task_gen.py，纯 CPU）

**任务定义**：`[STATE] 事实集 [CURRENT] e0 [GOAL] 关系路径 [ACTIONS] 候选边`；标签 = 唯一走通者的候选索引。三关系 P(有向)/M(对称)/S(对称)，实体池 300（匿名 E###）。竞争边断链深度 ∈ {0..hop-2}，为第二难度轴；hop1 结构性排除（剩余路径长 0 时动作不可能唯一）。

**路径表与切分**（manifest 冻结，SEED=2033）：

| 切分 | 路径 | hop | n | 候选数 | 背景干扰 |
|---|---|---|---|---|---|
| train | gp2=[P,P], sil2=[M,S], cousin3=[P,P,S] | 2–3 | 3600 | 3–5 | 2–4 |
| dev_random | 同 train | 2–3 | 600 | 3–5 | 2–4 |
| confirm_depth | gp4, gu4, sc5, kin6 | 4–6 | 500 | 3–5 | 2–4 |
| confirm_combo | uncle2=[P,S], inlaw2=[M,P], gp3=[P,P,P] | 2–3 | 240 | 3–5 | 2–4 |
| confirm_distractor | 同 train 路径 | 2–3 | 240 | 6–8 | 8–10 |
| pilot（不进对比） | train+uncle2+gp4+kin6 | 2–6 | 120 | 3–5 | 2–4 |

**审计结果（全过，`data/ldm_edge_action/manifest.json`）**：
- 答案唯一 + 动作唯一 + 候选闭包：6 切分共 5,300 条复检 0 错【实测】。
- 跨切分逻辑重叠：logical id / canonical key / 事实集全等 = 0【实测】。
- 答案位置：train 直方图与均匀期望卡方 p≈0.07（边界但可接受，如实记录；不因不显著而重掷种子）【实测】。
- 断链深度分布：confirm_depth 覆盖 0–4（403/440/430/160/70），非退化【实测】。
- 序列长度：符号数 p95：train 70，confirm_depth 109，confirm_distractor 123 → 上下文 ~160 符号余量充足【实测】。

**已知局限（如实）**：实体池跨切分共享（匿名池设计，同 T-13）；未做完整图同构检查，仅结构粗代理（goal+关系多重集+深度轮廓+候选数）——dev_random 589/600 命中属同分布必然，外推切分 0 命中；"同构不同实体名"的潜在泄漏未排除。

## §3 模型实现与 sizing（s63_ldm_model.py）

**实现**：双向 pre-norm Transformer（事实顺序随机打乱，因果掩码会破坏可用性）；正弦位置编码（无参数）；loop 变体 = Prelude 1 + 共享 Core 2 + Coda 1，推理轮数可调；dense 变体 = Prelude 1 + 独立 mid n + Coda 1。评分头为共享 `Linear(d,1)`，读候选实体 token 位置。退出控制器读取 pooled hidden + 轮次嵌入 + 4 维置信特征（maxp、margin、归一化熵、与上轮 KL）。

**分词**：符号级词表 320（实体 E000–E299→1–300、P/M/S、[STATE]/[CURRENT]/[GOAL]/[ACTIONS]/[ACT]/SEP/COMMA），无预训练词表。

**参数量（实测，`param_report`）**：

| variant | 总参数 | 共享 core | 说明 |
|---|---:|---:|---|
| loop r=1/2/4/6 | 1,855,682 | 889,728 | 总参数与轮数无关（权重复用） |
| dense mid=2 | 1,841,473 | 0 | + 退出模块 14,209 后与 loop 差 0.77% |
| dense mid=8 | 4,510,657 | 0 | 供同算力参考 |

loop 的 `unrolled_equiv_params`（按展开计）= 4,524,866（r=4），只是展开视图，不是参数效率口径。

**sizing（CPU，bs=8，含前反传）**：loop r=4 ≈ 0.084 s/step；dense mid=2 ≈ 0.03 s/step（首步含预热）。GPU（RTX 5060 Laptop 8GB）实测 bp=64 时 loop r=4 ≈ 0.052 s/step、dense ≈ 0.021 s/step，显存占用远低于 1GB。

## §4 冒烟诊断：发现两个真实缺陷（均未通过）

**结论先行：首轮冒烟未通过，未进入可行性实验。** 两个独立缺陷各自都足以解释失败，均已定位并修复，但修复后仍无泛化——见 §4.3。

### 4.1 缺陷一：零初始化切断整个子层梯度（模型 bug，已修）

按规格 D7 实施"Core/Coda 输出投影精确零初始化"后，梯度检查显示 `core.*.qkv.weight`、`core.*.up.weight`、`coda.*.qkv.weight`、`coda.*.up.weight` 全部 **grad=0**，只有被零化的 `proj`/`down` 有梯度。可训练容量实际塌缩为 1 个 Prelude 块 + 各块最后一层投影——不足以做关系组合。

修复：改为小方差初始化（`out_scale=0.02`）替代精确零，保留"初值接近恒等"的稳定意图而不切断子层内部梯度。A/B 实测：zi=False dev 0.327 vs zi=True 0.285（r=4，2500 步）——方向正确但幅度远不足以解决问题。

**规格 D7 需据此修正**：文献的零初始化是在完整从头训练 recipe 下验证的，直接搬到"冻结大部分容量"的小模型配方会变成瓶颈。此为对本项目 D7 的直接反证。

### 4.2 缺陷二：任务存在单步捷径（数据 bug，已修）

规则解法在 v1 数据上 100% 正确，但捷径审计发现：**68.9% 样本仅用 goal 首步（`goal[1]` 一步）即可唯一区分正确边**——因为干扰边断链深度均匀采样 0..k-2，绝大多数在第 0 步就断，模型只需判断"候选目标有没有下一步出边"，无需多跳。

修复（数据集 v2）：训练路径最低 hop 提到 3（hop2 剩余路径只有 1 步，结构上无法构造深断链），并强制每条样本至少一条"深断链"竞争边（断链深度 ≥ hop-2）。复检：**所有切分单步可区分率 = 0.000，全深度规则正确率 = 1.000**。

### 4.3 修复后仍失败：泛化为零

数据集 v2 + 非零初始化，3,000 步、全训练集（2,400 条）、GPU：

| arm | 训练 loss | dev_random acc | 随机基线 |
|---|---:|---:|---:|
| loop r=1 | →0.0000 | 0.293 | 0.264 |
| loop r=4 | →0.0000 | 0.258 | 0.264 |
| dense mid=2 | →0.0000 | 0.238 | 0.264 |

同时测得参照基线（dev_random，400 条）：随机 0.264、浅启发式（走一步）0.307、全深度规则 1.000。三臂均**等于或低于随机**。

**诊断实验**：
- 过拟合 32 条：loop r4（零/非零初始化）与 dense 全部 120 步内 loss=0、acc=1.0 → 无结构性 bug，管线正确。
- 单跳简化任务（goal 长度 1）训练集 100% → 模型能拟合，但同样不能作为泛化证据。
- 按 hop 分开训练：hop2 单独 1,500 步训练集 100%、hop3 同样 100% → 拟合能力正常。

**当前判读（强推断，未完全隔离）**：2M 参数 + 300 个独立随机初始化实体 embedding + 2,400 条样本，模型走的是"实体关联记忆"而非图遍历算法。任务本身要求学习一个与实体身份无关的算法（沿关系边遍历到底），而当前配方没有给模型任何共享结构来归纳这一点。

未验证的替代解释：优化步数不足（3,000 步约 200 epoch，已接近饱和但未做更长程）、学习率/正则不匹配、序列编码缺少显式边结构标记。

### 4.4 下一步（需决策，未自行推进）

1. **改名不换药**：仍是实体查表问题，不是循环深度问题。优先方向应是**让算法可学**，而不是加大模型：
   - 实体身份随机重映射（每次 epoch 重排编号），强制模型不能依赖编号记忆；
   - 或在输入中显式给出边结构标记（每条事实已含 subj/rel/obj，但可加边 ID 或邻接提示）；
   - 或缩小实体池（如 30 个）以提高同一实体在训练中出现的频率，让"沿边"模式更容易被学到——代价是降低组合泛化难度。
2. 上述任一改动都会改变任务契约，需先确认再改数据（当前 v2 已冻结并留档）。
3. 冒烟结论：**模型与数据管线可用，任务可解，但当前配方的泛化能力未建立**。在解决之前不进入退出控制器训练，也不做任何效率主张。

## §5 冒烟第二轮：单轴干预矩阵与文献对照（全部未解锁泛化）

§4 修复后泛化仍为零。系统性地逐轴干预（每项独立测试，其余不变）：

| 干预 | 对照值 | 结果（dev_random） |
|---|---|---|
| 数据量 2.4k → 24k（v3，`data/ldm_edge_action_v3/`） | 0.27–0.32 | 0.24–0.31，训练 loss 不再归零（1.40→1.04 慢降） |
| 调度 OneCycle → 恒定 LR 1e-3（24k 步） | 同上 | 0.24–0.31；训练 loss 降至 0.27–0.60，dense hop4 dev 反降至 0.19 |
| 编码：逐 token → **融合编码**（每事实一个位置 = subj+rel+obj embedding 之和；动机：逐 token 下第一层无任何位置同时携带(实体,关系)，须先学位置绑定） | 同上 | 拟合显著加快（loss 0.22 vs 0.52）但 dev 仍 0.27–0.31 |
| 实体池 300 → 48（`data/ldm_edge_action_v4p48/`） | 同上 | 0.24–0.29 |

**结论：便宜的单轴空间已穷尽，全部无效。**

### 5.1 文献对照（Saunshi arXiv:2502.17416，ICLR 2025，已读原文核实）

其 pp-hop 任务（与本任务同构类别）的 from-scratch 配方：

| 维度 | Saunshi pp-hop | 本项目当前 |
|---|---|---|
| 输入 | 扁平 token 序列，字母表 **4**，无绑定问题、无干扰、无候选集 | 300/48 实体 + 3 关系 + 干扰事实 + 候选集评分 |
| 训练数据 | **400 万**条 | 2.4 万（少 166×） |
| 呈现总量 | 200k 步 × bs 256 = **5,120 万** | 24k 步 × bs 64 = 150 万（少 34×） |
| 模型 | d=128, 8 头, RoPE, Adafactor 1e-3, warmup+cosine | d=192, 4 头, sinPE, AdamW（模型反而更大） |
| 结果 | 1 层×6 循环 = 99.9%（p=16/32） | 随机基线 |

关键：其模型不比我们大（d=128 < 192），**差距在数据/呈现量 1.5–2 个数量级**，且其任务更简单。grokking 文献（Power et al.）的标准图像为"训练集拟合 → 长平台 → 泛化突跳"；我们 24k 数据下训练 loss 仍停在 0.3–0.5，拟合未完成，平台期未开始。

### 5.2 100k 步 grokking 延迟探针（已完成，阴性）

配置：融合编码 + 恒定 LR 1e-3 + v3（24k）+ loop r=4，100,000 步（57 分钟 GPU，`results/ldm_gpu_grokking_probe_100k.json`）。

结果：训练 loss 在 ~50k 步后进入 0.02–0.27 区间（拟合基本完成），其后 50k 步 dev_random 始终平在 0.24–0.31，无任何抬升趋势。**在当前任务难度与数据规模下，未观察到 grokking 转变的迹象。**

注意该探针的边界：呈现总量 6.4M 仍比 Saunshi 配方低 8 倍，且任务更难（300 实体 + 干扰 + 候选集 vs 字母表 4 的裸序列），故"文献级规模是否解锁"仍是开放问题——但已排除"差几步就到"的乐观情形。

## §8 MVT（最小可行任务）数据集冻结 + 三层判读预注册（2026-10-24，跑前写定）

### 10.1 第 3 层阴性的文献归因（2026-10-24 核实原文）

**归因结论：非框架 bug，是"训练体制未满足文献中循环外推的成立条件"。**

证据链（内部）：
1. dense 臂与 loop 臂**同败**（外推均随机）——失败位于三臂共享层（任务/编码/训练体制），非循环机制层；若循环框架是原因，dense 应表现不同。
2. 四层中 1/2/4 全过——实现无缺陷；remap 消融证明无记忆捷径。
3. 失败形态 = "训练分布满分 + 外推随机"，与下述文献预测的形态一致。

文献依据（均核实原文）：
- **Delétang et al., *Neural Networks and the Chomsky Hierarchy*（arXiv:2207.02098，ICLR 2023）**：固定深度 Transformer 处于 Chomsky 层级低层，非正则任务（需无界组合）长度泛化失败，且"容量足以拟合训练数据仍不泛化"——直接解释 dense 臂失败的理论预期。
- **Fan et al., *Looped Transformers for Length Generalization*（arXiv:2409.15647，ICLR 2025）**：权重绑定循环 Transformer + **自适应迭代数**可大幅改善长度泛化，但前提是"每次循环实现迭代算法的一步"（RASP-L 型算子）。我们的训练分布（hop≤3）存在 1–2 block 的注意力捷径，梯度从不要求 r>1，core 收敛到快捷解而非"每轮一跳"算子（退出控制器学出全 1 轮即其表征）。
- **UT（arXiv:1807.03819）**的正向外推（训练长度 40 测 400）在递归与序列位置天然对齐的 seq2seq 任务上取得；**Saunshi pp-hop 未测训练深度以外的外推**（原文无 beyond-depth 表）——文献并无"训练 hop2-3 自动外推 hop4-6"的承诺，本阴性不与任何已发表正结果矛盾。
- **Balesni et al., Two-Hop Curse（arXiv:2411.16353）**：浅组合任务天然存在捷径解，不强迫算法解——与 remap 消融后"学到的是快捷算法而非逐步算法"的判读互补。

**框架层设计缺口（vs 文献配方，非 bug）**：(a) core 内无每轮迭代信号（UT 有坐标嵌入刷新；round_emb 只喂退出控制器）；(b) 静态位置编码；(c) 训练分布不需要多轮。对应修复 = §10 排队的两项：深断链任务改版（使每轮有区分价值）与过程监督（强制轮次-步数对齐），再加可选的 core 内迭代嵌入。

### 12.2 两个干净的诊断发现

1. **存活头统计捷径（MVT-2）**：训练里"第 4 轮 ≈ 87.5% 候选已死"（链长与 hop 完全相关），模型学会按轮次查统计先验而非沿链计算——外推集第 4 轮实际全员存活，存活头精度 **0.14**（近乎全错）。修法（MVT-3 断链深度均匀化）立竿见影：存活头 r1–4 恢复 0.95+。**教训：过程监督的真值若可由 (hop, 轮次) 统计推出，监督反而教出捷径。**
2. **轮次惰性签名**：所有配置下 dev 精度对评测轮数 r 全平（MVT-3 薄 core 除外，+5pp）——即使 1 块 core，单轮（prelude+core+coda=3 block）就能以 0.91+ 解 hop2–5。循环在功能上是固定深度网络，轮次从未成为计算载体。

### 12.3 归因链（闭合）
外推失败 ≠ 监督/对齐/任务深度不足（三者已逐一修掉），**剩下的阻塞是双向全注意力在本任务上的并行组合容量**：候选位置全局可见所有事实，3–4 个 block 内可并行组合出 4–8 次链式查找，训练分布总在并行能力圈内，轮次永远"无活可干"；超出并行圈的深度（hop10+）则直接不可学（分布内也 0.6）。与文献对照：Saunshi/UT/Fan 的成功场景为字母表 4、p=16–32 长链、n=256 且多为填充符——并行捷径在那种结构里不可行，且预算为 400 万样本×20 万步（我们 12k×12k 步，差 2 个数量级）。

### 12.5 缺陷定性（2026-10-24 补记，应 @用户 指正）

§12.3 的"并行容量阻塞"应进一步定性为**框架设计缺陷**而非单纯的"任务不匹配"：

1. **缺陷判定标准**：框架设计目标 = "共享参数轮次换计算深度，难题多想几轮"。实测 = 轮次对答案零贡献（dev 对 r 全平）+ 退出控制器学成全 1 轮 + 外推全平。核心机制在目标场景内永久休眠，属设计失效，非"未启用"。
2. **缺陷来源（设计流程层）**：双向全局注意力（理由成立：事实乱序）与全状态摊开编码（理由成立：消除绑定瓶颈）两个各自正确的选择组合出并行捷径高速公路；设计评审缺少"单轮可解性检查"这一步。与 4B 线"单层短路未验深度必要性"同构——**两条线同一类流程缺陷：未在架构层验证深度的必要性**。
3. **论文表述建议**：作为 negative result 的核心教训——循环架构设计必须先验证"并行捷径不可行"，否则轮次惰性会使全部循环机制（含自适应退出）退化为常数函数；该检查应成为循环架构设计清单的第一项。

**修复方向增补**（原 §12.4 之外）：方向 4（架构侧）——限制单轮并行能力使"每轮一跳"成为唯一解：因果化注意力 / 限制每轮信息移动为局部邻域 / 稀疏化注意力掩码。与方向 1（任务结构改造）构成"改任务 vs 改架构"的对偶选项。

## §14 方向 3：parity 任务族（2026-10-24，预注册于跑前）

**任务**（s68，PonderNet 原文协议）：64 槽二进制位，答案 = 1 的个数奇偶（二分类，随机 0.5）；训练 k∈[1,48]，外推 96 槽 k∈[49,96]。选 parity 的理论依据：注意力为线性聚合，模 2 计数不可单次前向完成（Hahn 2020 经典硬例）——并行捷径原理上不可行，与图任务（单次内容匹配一跳）构成精确对照。编码零改动复用（槽=自环事实，P=1/M=0 位；EVEN/ODD 二候选；hop=k）。数据审计：奇偶平衡、跨切分重叠 0。

### 17.4 判定修正（2026-10-25，应用户方法学质询）——"证伪"降级为"实验未分离假说"

§17.2 的"承重假说证伪"是**跳跃式结论**，予以修正。三条强关联证据表明该实验从构造上就无法检验假说：

1. **需求-容量定量核算【实测】**：MVT-3 断链深度均匀化后，每样本最小串行需求（消除法：只查竞争链至断点，d+1 次查找）分布为 ≤1:53.8% / ≤2:81.2% / **≤3:94.0%**；单轮容量≈3 次查找 → 覆盖 94.0%。实测 bd=1 sup 的 r1 精度 **0.944 ≈ 0.940 理论覆盖率**（几乎重合）——轮次理论增益空间仅 6.0pp，实测 +1.2pp。**任务构造没给轮次留舞台**。
2. **训练协议与文献相反【文献原文核实，Fan et al. arXiv:2409.15647】**：其训练用**每样本精确步数 T_i**（T(n)=n 类，损失施加在 f_{T_i} 上）+ 长度课程；我们全程用 D8 随机 R——这训练的恰是"任意轮数可作答"（深度鲁棒读出），**与轮次承重直接对立**。我们反复观察到的"dev 对 r 全平"是 D8 的训练目标本身，不是轮次无能的证据。
3. **理论边界【Feng et al. arXiv:2305.15408】**：有界深度 Transformer 直接作答串行问题需超多项式规模；串行深度必须由某种展开机制供给（CoT 或循环）。轮次作为深度供给源在理论上正当，问题在构造。

**修正后结论**：瓶颈矩阵阴性 = 三混杂（任务需求<单轮容量、D8 与承重对立、h0 全额重注入）下的未分离结果。承重假说回到**未检验**状态。决定性实验见 §18。

## §18 决定性实验：exact-T 承重测试（预注册于跑前；文献配方对齐 Fan et al.）

**设计要点**（逐条对应 §17.4 三混杂的反制）：
1. **任务 MVT-5**：深断链（竞争边断链深度恒 = hop−2）→ 每样本最小需求 = hop−1（**全员顶格**，单轮容量 3 查找只覆盖 hop≤4）；训练 hop 2–6（需求 1–5），外推 hop 7–8（需求 6–7）。
2. **训练协议 exact-T**（弃 D8）：每样本轮数 R = hop−1（恰好所需），损失只施加在 f_R 终读出——对齐 Fan 的"ground-truth iteration count in training data"。**这是与 D8 的本质区别：不再训练任意轮可答。**
3. **位置编码**：新增 `--pos none`（NoPE，Fan 同款；事实集合无序，语义上正无位置）。sin 与 none 双臂。
4. 读出仅在终轮（Fan FAP 同构）；核心仍薄（1 块）+ h0 注入（Fan 同款）+ 轮次注入；瓶颈 bd∈{0,16} 次要轴。

**矩阵**：{pos: sin, none} × {bd: 0, 16} = 4 配置 × seed 17（12k 步，MVT-5 12k 样本）；终评 r∈{1,2,3,4,5,6,8} × {dev, confirm(hop7-8)}，另按 hop 分解。

**预注册判读（跑前写死）**：
- **承重成立**：dev_r5（=需求上限）≥0.85 且 dev 精度随 r 单调上升（低 r 在 hop5-6 上系统性失败、高 r 修复）——Fan 签名；外推 hop7-8 在 r≥6 档 >0.60 为外推 bonus。
- **承重证伪（这次是真证伪的条件）**：exact-T + 顶格需求下，hop5-6 在 r=5（容量充足）仍不达（<0.7）或精度对 r 无依赖——即权重共享轮在需求明确、监督对齐时仍无法供给串行深度。此时承重假说在该规模被干净证伪（与 Fan 小模型正结果冲突 → 归因规模/优化，另立假说）。
- **部分**：hop≤4 全对、hop5-6 部分恢复（0.7–0.85）→ 记录边界，加密 hop 轴再判一轮。
- 判读只看 dev 主判据；外推仅 bonus 不影响主判定。

### 18.1 结果（2026-10-25，4 配置，本机）——证伪条件字面触发，但鉴别诊断否决"干净证伪"

| 配置 | dev | r1/r5（各轮全平） | by_hop |
|---|---:|---|---|
| none+bd0 | 0.554 | 0.581/0.556 | hop2=0.90，**hop3–6 全 0.4–0.57** |
| sin+bd0 | 0.578 | 0.600/0.595 | hop2=0.99，hop3–6 全随机 |
| none+bd16 | 0.523 | 0.566/0.554 | 同上形态 |
| sin+bd16 | 0.509 | 0.556/0.591 | 同上形态 |

字面判读：证伪分支条件满足（hop5-6 在 r=5 <0.7 且精度对 r 无依赖）。

**但鉴别诊断否决干净证伪**【实测】：
1. **训练 loss → 0.0001–0.019（训练集完全拟合）而 dev hop3 起全随机**——这是"记忆不泛化"，不是"深度供给失败"。
2. **hop3 也塌了**：hop3 需求仅 2 次查找、单轮容量（3）绰绰有余；对照 MVT-2（同深断链数据、混批 + D8 训练）hop3=0.88。hop3 的塌陷与轮次/深度无关，指向配方混杂——首要嫌疑：**exact-T 的按 hop 分组批**（批内全同 hop，梯度多样性骤降，且模型可用 hop/R 身份做组内捷径）+ 12k 唯一样本被分组记忆。
3. Fan 原文另有两项我们未复制：**课程**（长度从小到大渐进）与**充足数据量**（其数据生成近乎无限，防止记忆）。

**判定（保守）**：承重假说第三次回到"未干净检验"。失败归因链：分组批记忆 > 数据量不足以防记忆 > （最后才是）轮次深度供给。下一步配方（若继续）：混批 + 逐样本 exact-T（需按样本变长 R 的批内掩码实现）+ Fan 课程 + 样本量 ≥100k（流式）。工程量明显上升，且与 2B 文本通道（已兑现正结果）竞争资源。

**决策建议**：循环线已连续三次"实验设计混杂→重做"，边际信息收益递减；按 PHASE_PLAN 分支，主线收益取向仍指向 2B。是否再迭代一轮 exact-T（改混批+课程）由用户定。

### 18.2 第四次迭代（用户拍板"快跑"；s71，预注册于跑前）

**配方**（修正 §18.1 三混杂）：混批 + 批内 per-sample exact-T（rounds_mask 冻结已停样本，R_i=hop_i−1）+ 流式无限样本（防记忆）+ Fan 课程（hop 上限 2→3→4→5→6 逐级，各 1/5 步）；20k 步、bs64、薄 core、r_max=8、双配置 {sin, none}×bd0。烟测（2k 步）：hop3=0.825 恢复泛化（对照 §18.1 分组批 0.45），by_hop 梯度衰减无断崖——混批修复有效。

### 19.4 V3a 修复迭代 + 深度诊断——退出控制器在冻结骨干下**结构性无信号**【实测】

### 19.6 V3 失败根因闭环（诊断 + 文献核实，2026-10-25）

**诊断【实测】**：联训 ckpt 控制器输出 **q≡1.00**（200 样本 × 8 轮 × 全深度，无一次停轮）。机制：联训用了 rounds_mask 冻结——样本过 T 轮后状态冻结，第 8 轮读出=第 T 轮读出=正确 → 软退出损失下"永远继续、权重全压末轮"与"在 T 停"**损失严格相等**，退出头零成本满分、从未学停轮；且 E[R] 恒 8 使 ponder 项常数化（无梯度）。**训练在"晚停免费"世界、推理在"晚停有害"世界（V4 过冲实测）——语义错配**。

**文献核实（PonderNet 原文重读）**：其训练恰好两面都做对了——①**训练时跑满全部 N 步、不做任何冻结**，损失是各步预测按停轮分布加权的期望（晚步错→受罚→真梯度逼停轮）；②停轮分布对几何先验的 KL（β 项）防塌缩、以 CE 同量纲提供停轮激励（ACT 的 τ 项即因这类失稳被诟病）。我们 V3c 同时违反①②。

**第四次修复设计（预注册，§19.7 执行）**：PonderNet 损失完整移植——联训**去掉 rounds_mask**（全样本跑满 r_max，无冻结；V4 世界里过冲毁答案→"永远继续"开始付出真实代价）；p_t 为几何截断归一的停轮分布；损失 = Σ p_t·CE_t + β·KL(p_t‖几何先验 λ_p)，λ_p 取先验均值≈E[T]=3（β=0.1 起）。判据沿用 V3：硬退出 ≥oracle−2pp、mean_rounds≤3.5、vs r8 省 ≥50%、停轮一致率 ≥0.9。

- **逐 hop 自适应分配（τ=0.3）**：hop2→1.00（acc 1.00）、hop3→1.00（1.00）、hop4→1.39（0.985）、hop5→3.00（0.96）、hop6→1.07（0.49）。即：能答的简单档几乎全 1 轮停；hop5 给 3 轮（feasible=3）精确匹配；hop6 骨干未学会（0.49），控制器只给 1.07 轮——**在不会的题上不多花算力**，这是符合期望的行为（但 hop6 未解是独立缺陷）。
- **feasible 表**：{2:1, 3:1, 4:1, 5:3}——注意 hop6 在任何固定 r 下都不到 0.95，故不进入 feasible 表、不计入 match_feasible（0.935 的分母不含 hop6）。这一点在论文里必须写明，避免把"hop6 未解"藏进指标。
- **τ 敏感性仍存在**：τ≥0.5 全部塌缩到 8 轮（q 集中在 0.73–0.80 窄带）。PonderNet 原文用**采样**停轮而非阈值；我们按 A4 判定"质量门内有可用 τ 即不算塌缩"，但**窄带 q + 阈值推理是这一配方的已知脆弱点**，论文需如实写成限制条件（建议后续用分位数校准 τ 或改采样）。
- **作答压缩（附带发现）**：feasible={2:1,3:1,4:1,5:3} vs exact-T 对角线 {hop:hop−1}={2:1,3:2,4:3,5:4}——PonderNet 期望损失使骨干把串行链步压缩进更少轮次（hop5 从需 4 轮变 3 轮）。对省算力是正面证据，但削弱"轮次=串行深度"的机制叙事，需脚注。
- **与 V1 对照**：V1 exact-T 的 hop6=0.96；V5b PonderNet 的 hop6=0.49。同一 30k 预算下 PonderNet 目标在最难档明显吃亏（梯度被 8 轮读出+退出头分摊），这是配方代价而非退出机制失效。

**§19.7 收官定性**：
- **PonderNet 损失修复成功**：V3c 的 q≡1.00 死态被彻底打破；四判据全过；控制器在简单档零浪费、在最难档不多花，中间档精确匹配；省 81% 计算且质量在 oracle−2pp 内。
- **已知缺陷三条（如实收档）**：①hop6 未解（PonderNet 预算代价，非退出机制问题）；②τ 窄带敏感性（阈值推理 vs 原文采样）；③match_feasible 分母不含 hop6（指标口径需在论文中披露）。
- **退出线就此闭环**，不再追加配方。下一步由用户决定：2A 放大重训（含 PonderNet 退出头联训 + 更大预算解 hop6）/ 2B 文本通道在线验证 / 先做论文整合。**均需用户明确授权后才启动。**

## §19.8 补验证：seed 复现 + 深课程外推（2026-10-26，两项均已完成）

**动机**：§19.7 的 V5b 正结果只有单一 seed，且深度外推（confirm hop7/8）在所有历史评测中恒为 ~0.5（随机），两项都必须在 2A 放大前钉死。

### A. seed 复现（同配方、同数据、仅换 seed 23；`results/iter4_v5b_ponder_s23.json`）

| 指标 | seed17（V5b） | seed23 | 判读 |
|---|---|---|---|
| fixed-r oracle | 0.893 | **0.803** | 差 9pp |
| feasible 表 | {2:1, 3:1, 4:1, 5:3} | **{2:1, 3:1, 4:1}（无 hop5）** | hop5 未学会 |
| τ=0.3 acc | 0.887 | 0.803 | — |
| mean_rounds | 1.49 | 1.20 | — |
| match_feasible | 0.935 | **0.672** | **未过 0.9** |
| 逐 hop 精度(r8) | 2:1.00 3:1.00 4:1.00 5:0.98 6:0.49 | 2:1.00 3:1.00 4:0.99 **5:0.49** 6:0.50 | hop5 崩 |

**结论：V5b 的正结果未复现。** 失败模式明确——seed23 的 **hop5 骨干从未学会**（任何轮数 0.49–0.53 = 随机），因此 feasible 表里没有 hop5，控制器对 hop5 只给 1 轮（因为答不对），match_feasible 掉到 0.672。这不是控制器问题，是**骨干在最难三档（hop5/6）的收敛对 seed 高度敏感**：seed17 恰好解出 hop5、seed23 没有。
- 定性修正：§19.7 的"四判据全过"是 **seed17 单点结果**，不能作为可复现的正结果陈述。按双种子口径，退出线的诚实状态是：**hop2–4 稳定（两 seed 均 1.00/1.00/0.99），hop5+ 不稳定（seed 依赖），hop6 两 seed 均未解（≈0.49）**。
- 控制器机制本身在 seed23 上仍工作（hop2–4 全 1 轮停、零浪费，mean_rounds 1.20 省 85%）——**"能答即停"策略是可复现的；"解到多深"不可复现**。这是两件事，必须分开陈述。

### B. 深课程外推（exact-T 配方，课程 2,3,4,5,6,7,8，r_max=10，40k 步；`results/iter4_v6_hop8_s17.json`）

- 总体崩溃：dev_r8 = 0.499，hop2/3/4/5 在 r8 分别 0.56/0.30/0.745/0.225——**不是"学会了但外推差"，是训练本身失稳**。
- **但崩溃形态给出决定性证据（本轮最有价值的发现）**：逐轮 by_hop 出现清晰的**轮次-难度错位映射**：
  - r3：hop2=0.965、hop3=0.005、**hop4=1.0**、hop5=0.03
  - r5：hop5=0.015、**hop6=0.99**
  - 即 hop_k 的答案出现在第 k−1 轮——**模型确实建立了"按轮次作答"的机制，但轮次基准整体偏移 1**。
- 定性：这不是容量不足，也不是学不会深跳，而是 **r_max=10 + 课程推 8 时轮次索引基准漂移**。可修（对齐 r_max 与课程上限、或显式监督轮次），但本轮不做——按纪律先记录。

### C. 本轮工程事故（第三次重复，已加机制防护）

- 同一 `--out` 再次出现双进程并发写（旧进程未死 + 新续跑），已 `Stop-Process` 清理并保留单一进程。
- **已在 s71 加文件独占锁**（`<out>.lock` + `msvcrt.locking`）：同一 `--out` 第二条进程会直接 `SystemExit` 报错。此后不会再发生。
- 教训固化：`wmic`/PowerShell 查进程可能因会话隔离看不到；判定"是否在跑"应查**文件时间戳是否推进** + **精确匹配 commandline 中的 `--out` 路径**，不能只数进程数。

### D. 对 2A 的含义（不含决策，仅事实）

1. **退出控制器机制**（能答即停、零浪费）两 seed 可复现 → 可以作为配方组件带进 2A。
2. **骨干解到 hop5/6 不稳**（seed 依赖） → 2A 必须多 seed 或更长预算，单次跑出的"解到 hop6"不可信。
3. **hop7/8 外推从未成功**，且崩因是轮次基准偏移而非容量 → 2A 若要做外推，须先修轮次对齐（r_max=课程上限）。
4. **这两项补验证都没通过**，与 §19.7 单点正结果合起来看：退出线是"机制成立、骨干深度不稳、外推未解"。

## §19.9 多 seed 承重验证 + 训练基础设施（2026-10-26）

**背景**：§19.8 暴露 V5b 的 PonderNet 正结果只有单 seed。本轮改用 **exact-T 目标**（不吃退出头的梯度分摊）跑多 seed，专测"hop5/6 能否稳定解出"。

### A. seed 汇总（exact-T，课程 2,3,4,5,6，24k 步，r_max=8）

**最终比例：2/4 五级全解（seed17、seed41），2/4 失败（seed31 只到 hop3；seed53 全程未收敛，峰值 r8=0.68@8k）。**
- seed53 加深到 32k 步、eval 加密到每 2k 次，仍未救回——轨迹从 8k 的 0.68 单调震荡下滑到 0.49，**不是"训练不足"，是该 seed 的优化轨迹本身发散**。
- 论文表述：**"4 次独立运行中 2 次解出全部难度（含 hop5/6），2 次失败"**。这是 mechanism-feasible 而非 reliable 的结论。失败率 50% 是真实数字，不能淡化。

### B. 对角矩阵（seed41 @ 24k，本线最干净的承重证据）

```
      r1      r2      r3      r4      r5      r6      r8
hop2  1.000  0.465  0.080  0.260  0.750  0.940  0.900
hop3  0.975  1.000  0.990  0.900  0.565  0.270  0.130
hop4  0.880  0.980  1.000  0.995  0.995  0.995  0.950
hop5  0.465  0.720  0.895  0.975  0.980  0.985  0.975
hop6  0.490  0.450  0.615  0.865  0.925  0.955  0.975
```

三条独立证据同时成立：
1. **r1 列的分层**：hop2=1.000 而 hop5=0.465、hop6=0.490。同一前向、只跑 1 轮时简单题全对、难题半对——**排除"并行捷径一次算完"**。若能一次算完，r1 应全高。
2. **峰值位置随难度后移**：hop2→r1、hop3→r2、hop4→r3（严格 hop−1）；hop5→r6、hop6→r8（课程上限 6，峰值被推后）。
3. **过冲惩罚**：hop3 在 r2/r3 为 1.000/0.990，到 r6/r8 掉到 0.270/0.130——跑多了反而错，符合"轮次=计算步数"的过冲语义（与 V4 实测一致）。

### C. 后期遗忘是真实风险（影响训练策略）

- seed41：20k 时 r8=0.916（五级全解）→ 24k 掉到 0.786（hop3 崩至 0.13）。
- seed31：全程未超过 0.76。
- **对策已实现**：`--early-stop`——课程覆盖的全部 hop 在 dev_r8 均 ≥0.95 时立即停训并存 `_EARLYSTOP.pt`，防止过冲把峰值态训坏。

### D. 本轮新增训练基础设施（可直接用于后续 0.8B）

1. **实时面板** `s73_ldm_dashboard.py`（http://127.0.0.1:8752）：只读、独立进程、不碰 CUDA；展示每 run 的 RUNNING/STOPPED、step/cap/loss、固定 r 精度曲线、**hop×r 热力图**、PonderNet 判据。3 秒刷新。
2. **存档点**：每 eval 写 `_ckpt.pt`（纯权重）+ `_state.pt`（含 optimizer/sched/RNG/step/hist/evals_hist/milestones，支持 `--resume`）。
3. **永久转折点存档**：任一 hop 首次 ≥0.95、或 ≥4 hop 同时达标 → 写 `_MILESTONE_s{step}.pt`，索引记入 `milestones`，**不随后续 eval 覆盖**。本轮 seed41 靠它保住了 20k 峰值态。
4. **早停**：见 C。
5. **并发写防护**：`<out>.lock` 独占锁（`msvcrt.locking`），同一 `--out` 第二条进程直接报错退出——此前已发生三次文件竞争事故。
