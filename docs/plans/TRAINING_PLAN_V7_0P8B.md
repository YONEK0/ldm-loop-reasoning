# V7：Qwen3.5-0.8B 循环深度后训练与缓存优化计划

> 版本：V5，2026-10-17；基于 0.8B S3 两轮结果和代码路径审计修订。
> 状态：**质量追平训练计划已准备，执行暂停；未启动新训练或占卡测试。**
> 测算配套：`BENEFIT_AUDIT_0P8B.md`。本文件规定训练、缓存实现和优化验证。
> 目标：先让自适应退出追平最优固定深度质量，再验证真实早退、缓存和稀疏计算；不把退出深度下降直接当作质量或加速成功。

## 1. 已对齐的实验设计

两臂来自同一份原始 Qwen3.5-0.8B-Base 权重。A 为非循环后训练，B 为循环后训练。主对照锁定同数据、同数据顺序、同有效训练 token 预算、同 LoRA 作用层段与配置、同批量和同评测协议。

| 项 | A：非循环 | B：循环 |
|---|---|---|
| 主干 | 原架构单遍 | E/M/D，共享 M 权重并循环 |
| LoRA | 选定 M 区域的实际可用投影 | 同层段、同配置 |
| 新增模块 | 无 | 状态门、开关；自适应分支另含路由器 |
| 数据 | GSM8K train 中划出的训练部分 | 完全相同 |
| 主训练预算 | 同有效 token 数 | 同有效 token 数 |
| 推理缓存 | 标准完整缓存 | 每个逻辑深度独立的完整缓存 |

“同条件”是上述受控条件相同，不代表 FLOPs 相同，也不代表额外模块、辅助损失完全相同。B 是循环方法整体的处理臂；通过 B 内部消融判断各组件贡献。分别记录总参数、可训练参数、额外模块参数、训练 FLOPs/卡时，不把门和路由器的参数隐去。

**不能宣称 B 的 d=1 就是原始模型。** 当前门控并非严格恒等，后训练 LoRA 也改变了权重。训练前测量原始模型与改造初始化模型；训练后测量 A、B-d1、B 多深度和自适应版本。只有同权重、门/路由严格旁路、positions/masks/norm/head 一致的单遍路径，通过等价性检查后，才能作为原模型实现校验。

## 2. 数据与调参隔离

- 从 GSM8K 官方 train（7473 题）固定划出训练、验证、早退校准三个互斥部分；保存样本 ID、种子、内容哈希和切分清单。具体比例在执行配置中锁定，两臂共用。
- 验证集用于学习率、停止点、训练转折点、深度配置和模型选择；校准集用于退出阈值及可接受质量损失的选择。
- **GSM8K test（1319 题）不得用于早停、模型选择、升级决策或阈值调参。** 配方锁定后用于正式终测；若根据终测结果重新设计，必须披露该测试集已被反馈使用。
- 通用能力开发监控使用 wikitext 验证 split；正式报告使用 test split，预先固定分词、滑窗、截断与 PPL 计算方式。
- 数据增强只作为后续候选。先核实与验证/测试集的重合和来源，再在两臂同步使用；不能只给 B 更多训练数据却仍声称同预算。
- token 总量由实际 tokenizer、模板、截断和 packing 清点，区分输入 token、监督 token、padding。删除此前约 1.1M token/epoch 的未核实数。

## 3. 开发与训练顺序

### S0：配置核对、单遍路径、因果性和完整缓存

读取实际模型 config、参数形状和 library 版本；确认层类型、注意力头、卷积窗口、text/vision 参数统计。层切分根据测量候选决定，不照搬 4B；定位只使用训练/开发数据。LoRA target 名称依据实际 GDN/attention/MLP 模块映射，不能仅使用普通 q/k/v 名单假定全部覆盖。

实现固定深度的完整缓存，先从 d=1 开始，再验证 d=2/4/8。正式训练前至少通过结构、因果 mask 和可缓存性的小规模检查，避免训练出的模型无法正确增量推理。代码开发可并行；任何模型运行仍遵守占卡授权。

### S1：双臂冒烟与配置定档

短程训练检查 loss、梯度、门/开关、数值稳定性、显存和吞吐，校准有效 batch、lr 和 token 统计。正式实验从共同原始 checkpoint 与锁定配置重新开始；若选择续接冒烟，则两臂冒烟预算均必须计入。

候选初值为 LoRA r=16、alpha=32、dropout=0.05，LoRA lr=1e-4、新增模块 lr=3e-4、cosine/warmup、clip=1.0、bf16、seq=2048。它们是待校准起点，不是 0.8B 已验证配方。NF4 属于后端条件选项，不能默认昇腾可用；两臂使用相同且已验证的权重精度方案。

### S2：核心双臂后训练

A 与 B 同有效 token 预算训练。B 首先验证固定循环深度是否带来质量收益，再进入自适应优化；候选深度为 1/2/4/8，实际支持的深度和深度采样策略按验证集定档，并存入配置。若多深度训练与固定深度训练有分支，分别编号，不混合归因。

沿用 LoopUS 状态门、首圈开关与 h0 注入作为候选方法组件。逐组件记录实现与来源，并保留 B-d1 单遍消融。soft decay=0.05 的全循环版本可作为现有方法参考，**不能作为已节省计算的早退版本**。

起步候选上限为 4 个训练 epoch，实际预算由切分后的 token 清点锁定。用验证集决定配对比较节点和停止点。保存各自最佳验证 checkpoint，但同时报告同 token 节点结果，避免不同停止预算混淆。

质量判定以 GSM8K strict 的两臂配对差异为主，结合 CE/PPL、重复与完成率。初步领先标为方向性；正式结果报告置信区间，资源允许时做多种子复核。不能把小样本领先或固定 3 个百分点自动当作已证明收益。机制证据要求存在有益的深度区间，不要求所有深度单调变好。

### S3：自适应与部署语义训练候选

固定深度模型稳定后，比较：

1. 全迭代软衰减参考：维护全部深度状态，作为质量与数值基准。
2. 真正跳过后续 M 计算的部署分支：先明确定义缺失 KV、conv state、recurrent state 如何处理，再训练/校准。

路由、ponder 系数和退出阈值由 0.8B 验证/校准数据确定，不把 4B 的平均深度 4.84 或 tau=1e-4 视为可迁移结论。

若部署分支需要额外训练，作为 B-opt 单独归档、单列 token/FLOPs/卡时。主 A/B 结果保持原预算；若比较 B-opt 的后训练收益，则给 A 匹配的继续训练预算，或明确这是未配平的部署优化实验。**删除“半个 epoch 必能修复”的承诺。**

LoRA 秩提高、M 全参、数据增强属于候选升级，不自动无限执行，也不保证拿到正收益。作用层段/秩/数据/预算变化时两臂同步匹配；新训练阶段仍需启动指令。

## 4. 质量追平优先路线（V5 新增）

### 4.1 S3 历史结果与问题归因

`s28_s08_s3.py` 的两轮历史实验保留为对照，不覆盖：`lam=0.1` 时 adaptive CE=1.0053、平均深度=3.85；`lam=0.02` 时 adaptive CE=0.99266、平均深度=4.25；固定最优 d2 CE=0.95647。退出深度下降成功，但质量门 `adaptive - fixed_best <= 0.005` 未通过。

代码审计发现旧 S3 训练路径不能把质量损失有效传给 router：每圈 hidden 在更新后被 detach，且最终 loss 只使用最后一个监督圈的 CE；硬阈值 `where(s >= tau)` 也不是可微退出路径。因此旧结果只能证明 router 能改变退出分布，不能证明它学会了质量保持的退出策略。

### 4.2 Phase Q1：可微自适应质量训练（新增脚本，不覆盖旧 S3）

目标是先追平固定 d2/d4 的质量，不宣称节省墙钟。训练采用 soft continuation probability：`q_t=sigmoid(router(h_t))`，`p_1=1`、`p_t=p_(t-1)*q_t`，`h_t=h_old+p_t*(h_new-h_old)`；质量路径不 detach，完整跑 B 圈作为训练参考。

损失由以下部分组成：

- `L_gold`：adaptive soft path 的真实标签 CE；
- `L_teacher`：冻结 d2 teacher 与 adaptive logits 的 KL 或 logit-MSE；
- `L_depth`：d1/d2/d4/d8 的轻量深度一致性约束；
- `L_ponder`：平均 continuation probability/有效深度惩罚，仅在 quality warm-up 后退火开启。

初始阶段 `lambda_ponder=0`，先验证质量梯度和 adaptive CE；再逐步增加 ponder。teacher KL/logit 对齐先限制在固定答案尾部窗口（默认 32 token），避免 8GB 显卡物化全词表全序列双分布造成显存峰值。alpha/beta/lambda、温度、窗口、阈值写入 checkpoint。训练前必须通过单 batch 梯度检查：router 参数的 adaptive CE 梯度非零。

资源预检：0.8B NF4/bf16 路径、`ctx=256,batch=1` 仅为保守起点；在正式预算前测峰值显存/稳态吞吐，再选择能够稳定运行的配置。不得因脚本默认值省略显存实测。

### 4.3 Q1/Q2/Q3 升级阶梯

- **Q1**：只训练 router，冻结 arm B LoRA、L1Gate 和 backbone；确认是否为旧训练图问题。
- **Q2**：Q1 未达到质量门时，开放 M 块 LoRA 小学习率做退出适配，E/D 冻结。
- **Q3**：Q2 仍未达到质量门，才考虑 M 块更大 LoRA 或 M 块全参；每一级独立预算和 checkpoint。

每一级最多一次短程超参筛选；不无限调参。测试集不参与任何选择。

### 4.4 Phase Q 质量门

每次 Q1/Q2/Q3 结束必须报告：adaptive CE 与固定 d2/d4 的配对差及 bootstrap CI、validation strict/完成率/重复率、退出均值与直方图、teacher KL、router 梯度和 ponder 曲线。

通过条件：adaptive CE - fixed-best CE <= +0.005；strict 不低于 fixed-best；平均深度小于 8 且至少 3 个有效退出深度；无系统性复读或格式崩坏。未通过则停止自动升级并归档失败归因。

### 4.5 Phase E：真实早退与系统优化（仅 Phase Q 通过后）

先定义并实现 `exit-skip` 的完整状态语义：全注意力缺失 KV、GDN conv state、GDN recurrent state 都必须处理；不能只广播 hidden。exact full-cache 继续作为参考。

G2/G2' 同时验证 teacher-forced logits/CE、自由生成 strict/完成率/重复率、长短上下文和 batch；补状态/路由/缓存/调度成本计入 FLOPs 与墙钟。未通过时保留 exact cache，不把理论层数减少称为实际加速。

随后按风险顺序做：完整 cache 预分配与分块写入；recursion-wise/shared-KV 消融；K/V 量化；FlashLoop 式 lazy update 独立研究分支；continuous depth-wise batching serving 实验。以上都不改变 Phase Q 的主训练结论。

## 5. 完整缓存设计与正确性验收

每个请求拥有独立缓存；E/D 各执行一次。M 的权重共享，历史状态按 `(depth, physical_layer)` 隔离：

- 全注意力：该层该深度的 K/V、逻辑长度及对应 token positions。
- GDN：该层该深度的卷积历史窗口、递归矩阵状态、初始化标志。
- 请求级：位置计数、mask、路由信息；清空/重排时同步处理所有状态。

先评估复用官方 cache 的包装与逻辑层索引，再决定需自写哪些部分。旧 s12 有初始化、跳过 M 的对照测试、未完整 prefill 等缺陷，**不能证明官方 cache 只能走 model.forward 或必须弃用**。锁定 Transformers 版本，不混用不同版本 cache/positions 接口。

完整 prompt 必须 prefill 后再 decode。全循环缓存的等价性有条件成立：参考路径本身因果、状态正确隔离、位置/mask 正确、每 token 每逻辑层只推进一次。不能仅凭字典结构称为 exact 已验收。

G1 验证包括：全位置 logits max/mean 差、CE 差、argmax 一致率、逐层 KV 长度与 GDN 状态；覆盖短 prompt、卷积窗口/chunk 边界、完整 prefill + 单 token decode、清空重用和真实路由退出。padding/batch/chunked decode 若要支持，单独验证。

数值容差先用 fp32 小规模参考区分逻辑错误与运算次序差异，再按 bf16/backend 校准并在性能实验前固定。不把 max|delta|<1e-3 写成 bf16 必然性质。阈值附近的路由差异也要单独报告。未通过正确性不得宣称有效加速。

缓存容量按实际形状统计：KV 为各逻辑层 `2×batch×length×kv_heads×head_dim×bytes` 求和，另加 GDN conv/recurrent、元数据、工作区和分配余量。删除“几十 MB、无压力”的未测承诺。

## 6. 优化路线及可行性边界

### O1：保持计算语义的工程优化（优先）

完整缓存先测 cache on/off；然后采用预分配/分块写入等方式减少每步 torch.cat 重分配与历史复制。固定请求长度和 batch 先验证，按 profiler 决定后续调度、图执行与融合算子优化。两臂使用同等级优化，不把普通缓存收益当作循环特有收益。

### O2：真正早退（研究分支）

退出后省去的 M block 必须实际未执行。全注意力的缺失条目，可实验“复制隐状态后经目标层 normalization、K/V projection、RoPE 补条目”或按深度活跃历史注意力；这些都是新的部署语义。

GDN 还必须规定未访问深度的 conv/recurrent 历史如何更新。冻结、基于近似输入的状态更新、或训练期就采用活跃历史语义均不是现有 soft-decay 的精确等价。状态补算开销必须计入 FLOPs 与时间；hidden 广播不能直接补出 exact GDN 历史。未定义完整规则前，不把 exit-skip 作为可上线模式。

G2 在独立校准/验证集上同时测同前缀 logits/CE 漂移和自由生成 strict、完成率、重复率，并覆盖短长上下文与输出长度。预先固定可接受质量损失，不能看正式 test 再选阈值。单 token 延迟与批处理吞吐分别报告。

### O3：部署适配（条件候选）

若 O2 质量退化，候选为部署语义训练、多深度监督、完整模型蒸馏或渐进过渡；必须具体规定 forward、损失和预算后再运行。LayerSkip、CALM、MoR 提供方向依据；MELT v2 是不同架构与两阶段训练参考，不是本计划的半 epoch 适配证明。G2' 重测，不通过则保留完整缓存为默认。

### O4：缓存压缩（分开验证）

- 全注意力 KV 跨深度共享：参考 Huginn/MoR，first/last 共享分别消融；单独测长生成退化，不默认无损。
- KV 量化：参考 KIVI，先从目标硬件可实现的精度试验；K/V 分布、量化误差、解量化开销均测量。其论文结果不等于我们的 NPU 收益。
- GDN 状态保持原精度和逐深度隔离作为基线；若压缩/共享 GDN 状态，另立实验，不冒充普通 KV 量化。
- FlashLoop 的 lazy 更新/稀疏注意力/残差量化列为后续参考，其 CUDA 实现和经验精度保持未证明可直接用于 GDN/昇腾。

### O5：昇腾与鲲鹏适配

先跑原模型完整缓存，核实芯片、CPU 架构、驱动、CANN、torch_npu、Transformers 和实际算子路径；再验证循环版、最后优化。不能默认所有 GDN 内核都会自动正确回退，不能从标准架构支持推导自定义循环可直接运行。

G3 检查同前缀数值/质量与状态生命周期。跨硬件不要求逐位一致；未通过的输出不能作为有效性能结果。两臂同精度同测量栈；分别注明融合/回退路径。原模型最优引擎可做额外部署参照，与同代码栈的架构对照分开。

## 6. 测算出口

输出 A、B 固定深度、B 自适应及 B-opt 的质量、总/可训练参数、FLOPs、首 token 延迟、逐 token 延迟、整题完成时间、输出长度、显存与吞吐曲线。扫描深度、上下文/生成长度、batch 和题型，测出优势与劣势区间。

同 0.8B 对照能回答“近似相同参数量下的后训练收益”，不能单凭质量/token 曲线证明普遍的参数缩减率。参数效率报告必须带实际参数计数与训练/推理成本。更大模型或非共享展开模型对照属于额外实验，未经用户同意不加入。

## 7. 运维

- 状态仍暂停；没有从本文档更新推导训练授权。
- 常规每 25 步可恢复检查点与评估转折点永久存档并存；普通步数备份不冒充永久成果档。
- checkpoint 保存模型、优化器、调度器、随机状态、数据位置、有效 token 数、配置与评估记录；意外中断先核对再恢复。
- 看板为训练监控，两臂并列展示 loss/lr/token/梯度/吞吐/验证质量，B 加门/路由/深度统计。
- 永久归档由验证 CE/质量趋势、机制变化等转折驱动，记录触发依据；终档单列。
