## 1. 研究问题

**一句话**：循环深度（同一组权重反复跑多轮）能否承载串行推理，且比同参数稠密模型更省参数？

**判定方式**：在可控的合成图任务上，看"第几轮答对"是否随任务所需跳数移动（对角/阶梯签名）。

---

## 2. 任务（MVT-5）

**形式**：符号图上的路径追踪。

- 输入：一组关系事实 `(subj, rel, obj)`、起点 `e0`、目标关系序列、2 个候选动作
- 问：从 `e0` 出发，走 `hop` 跳到达哪个候选？
- 候选：1 个正确 + 1 个"深断链"干扰项（干扰项的链长度 = hop−2，必须真走才能排除）
- 词表：320 个符号（E000–E299 + 关系/标记符）
- 难度轴：`hop ∈ {2,3,4,5,6}`（训练），`hop ∈ {7,8}`（外推测试集 confirm_depth）
- 编码：**融合编码**——每条事实占一个位置，向量 = subj+rel+obj 三个 embedding 之和。
  这样第 1 层注意力就能做关系 join（逐 token 编码需要模型先自学位置绑定）

**为什么用非函数式图**：早期用函数式图（每个实体只会有一条出边）时，模型发现
"不用循环、一次并行匹配就能答"，68.9% 的样本一跳可区分 → 学不到循环
（错误档案 E-011）。改成非函数式 + 深断链后，单跳不再可解。

**数据**：`data/ldm_mvt5/` 下 `train.jsonl`（12MB，流式生成器另存于 s66）、
`dev_random.jsonl`（1000 条，hop2–6）、`confirm_depth.jsonl`（hop7/8 外推集）。

## 3. 模型（s63_ldm_model.py）

```
LoopedDecisionModel(
  variant='loop', d=192, heads=4, ffn=768,
  n_prelude=1, n_core=1, n_coda=1, n_rounds=8,
  round_in_core=True, pos='none', bottleneck_dim=0
)
```

结构：`Prelude(1 层) → [共享 Core(1 层)] × R 轮 → Coda(1 层) → 候选打分头`

**关键设计**：
- **NoPE（无位置编码）**：必要。加正弦位置编码后对角线消失（H-002）。
  原因：绝对位置编码给了"这是第几个 token"的并行信息，模型可借此走捷径；
  NoPE 逼它只能靠循环状态累积。
- **每轮重注入**：`inp = carry + h0`，其中 `h0` 是 Prelude 输出
- **`round_in_core`**：每轮把 round embedding 加进 core 输入
- **候选打分**：`score = Linear(d,1)` 作用在候选位置的表征上（2 分类）
- **共享权重**：core 只有 1 层，跑 8 轮

**参数量（实测）**：

| 组件 | 参数 |
|---|---|
| token_emb | 61,440 |
| prelude（1 层） | 444,864 |
| core（共享循环体） | 444,864 |
| coda（1 层） | 444,864 |
| ln_loop / score / round_emb / exit_mlp / proc_head | 16,515 |
| **小计（无路径监督）** | **1,412,547** |
| step_head（路径监督，Linear 192→320） | 61,760 |
| **合计（当前配方）** | **1,474,307** |

展开等价参数（不共享时一次前向的权重用量）= 4,588,355。
**论文汇报口径：唯一可训练参数 1.47M；展开等价 4.59M，两者都要报。**

## 4. 训练配方演进（理解当前配方为何长这样）

### 4.1 第一代：exact-T（"只在自己那一轮监督"）
每个样本只在第 `R = hop−1` 轮被监督，`rounds_mask` 冻结已完成的样本。

**问题**：模型只学过"算完就停"，没有"算完继续跑"的经验。评测要跑 1..8 轮画对角线，
那些多跑的轮次处在训练分布外 → 一过冲就毁答案（错误档案 E-001 跷跷板）。

### 4.2 第二代：PonderNet（学退出）
照 PonderNet 原文实现：跑满 N 步 + 停轮分布的几何先验 KL。
**结果**：退出控制器学会了按难度分配轮数（能答即停），但代价是骨干的 hop5/6
掉到 0.49（梯度被 8 轮读出+退出头分摊）。

### 4.3 第三代：persist-sup（多轮保持监督）★当前保留
**改动**：从第 R 轮起，**每一轮都要求答对**（`mask[R-1:] = 1`）；
对 t<R 轮次用 0.3 权重轻压，防提前偷跑并行捷径。

**效果**：归零事件从 5 次降到 0 次；成功率从 0/8 提到 4/8；hop6 首次到 0.96–1.00。

### 4.4 第四代：step-sup（中间路径监督）★当前保留
**改动**：从数据的 `proof` 字段取逐步路径，第 t 轮额外预测"这一跳走向哪个实体"
（`step_head: Linear(192→320)`，权重 0.5）。

**效果**：在 4 个已确认失败的种子上，3 个被救回（hop5 0.50→0.98/0.99/1.00）；
总成功率 4/8 → **7/8**。

**代价（必须如实报告）**：
1. 训练变慢 3–4 倍（每轮多一次 320 类分类）
2. 需要过程标注（proof），不是所有任务都有
3. 曾怀疑会引入"查表捷径"，已排查：hop5 在 r1 只有 0.53、hop6 在 r1–r3 只有 0.45–0.48，
   必须跑到第 4–5 轮才答对 → **阶梯形保留，无捷径**

### 4.5 当前推荐配方
```bash
/root/miniconda3/bin/python s71_ldm_iter4.py \
  --pos none --persist-sup --step-sup \
  --curriculum 2,3,4,5,6 --steps 24000 --bs 64 --lr 1e-3 \
  --r-max 8 --seed <S> --early-stop --eval-every 2000 \
  --out results/R_<name>.json
```

## 9. 基础设施与文件地图

| 文件 | 作用 |
|---|---|
| `s63_ldm_model.py` | 模型 + 数据编码 + 数据集（含 step_ent 路径目标） |
| `s66_ldm_mvt_gen.py` | MVT-5 任务生成器（`gen_example(rng, split, hop, comp_mode='deep')`） |
| `s71_ldm_iter4.py` | **训练主脚本**（精确-T / PonderNet / persist-sup / step-sup） |
| `s65_ldm_gpu_smoke.py` | 评测函数 `evaluate()` |
| `s74_ldm_residual_diag.py` | 残差/梯度诊断 |
| `s77_watchdog.py` | 守护进程：检测灾变/停滞并记录（已在跑） |
| `s78_agent_loop.py` | **本编排器**（队列 + dsh 判读 + 报告） |
| `docs/hypotheses/` | 假说档案（三态命名：PENDING/CONFIRMED/REFUTED） |
| `docs/errors/` | 错误档案（带症状路由表） |
| `docs/plans/AGENT_PROTOCOL_DHES.md` | 你的执行手册（边界/队列/判据/记录义务） |
| `results/*.json` | 每个 run 的完整记录：`hist`（训练）、`evals_hist`（累积评测）、`milestones` |
| `results/*_MILESTONE_*.pt` | 转折点永久档（hop 首达 0.95 时自动存） |
| `results/*_state.pt` | 断点续跑状态（含 optimizer/sched/RNG/step/hist） |

**评测口径**：
- `dev_r{r}`：固定跑 r 轮的准确率（r ∈ 1,2,3,4,5,6,8）
- `dev_r{r}_by_hop`：按难度分组的准确率 ← **判读主依据**
- `confirm_r8`：hop7/8 外推集准确率
- 训练日志 `hist` 里每 1000 步一条：`loss`、`cap`

**判读要点**：
- 五级全解 = `dev_r8_by_hop` 的 hop2..6 **全部 ≥0.95**
- 别用"某个中间步的峰值"当达标；用 `early_stop` 或最终 eval
- 阶梯形验证：hop5 在 r1 应仍低（~0.5），到 r4–5 才高 → 证明是串行而非查表
