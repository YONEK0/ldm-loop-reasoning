## 1. 分区缓存：实现约束与排错记录（方法论文档级素材）

**方案**：Qwen3.5（GDN+全注意力 3:1 混合）的循环深度推理缓存，用官方
`Qwen3_5DynamicCache` 分区复用：E/D 各一份、M 每循环深度一份（本战役 d≤8）。
全注意力 KV 与 GDN 的 conv state + recurrent state 均按 `(深度, 层)` 隔离。

**三个已定位并修复的实现陷阱**（每条都有对照实验证据）：

1. **位置覆写**：`encode()` 内部 `pos_ids = arange(seq_len)` 会在单 token decode
   时把 rotary 位置错置为 0。decode 必须显式传绝对位置。证据：s24c 二分实验
   （手工 prefill+decode 漂移 2.5）→ 逐层 hooks 对比（24 层输出逐位一致，
   前向无问题）→ 定位到 pos_ids。修复后 14 步教师强制 decode 逐位一致。
2. **has_previous_state 机制**：transformers 5.3.0 的 GDN 以
   `conv_states[last_linear_layer]`（0.8B 为层 22）作"有历史状态"的判据。
   分区 cache 不覆盖层 22 时（E/M 区），prefill 后必须给该槽补非 None 占位，
   否则 decode 时 GDN 走 `initial_state=None` 分支、丢失 prefill 递归状态。
   证据：未 seed 漂移 24.7 → seed 后部分改善 → 结合位置修复后全对。
3. **验证语义**：缓存正确性必须用**教师强制**喂 token 对比；用自生成 argmax
   token 对比教师强制参考会产生"生成 vs 原文"的分叉假象（第 7 步起 diff 25+
   假警报）。证据：s24 主脚本修正前后对照。

**最终门禁结果**（results/s24_s08_cache_check.json）：
C1 单遍等价 logits 逐位一致（maxdiff=0.0）；C2 确定性 0.0；
C4 分区缓存教师强制 decode d=1/2/4 的 max diff 0.25–0.76（bf16 运算次序级，
与官方全模型 cache 链同级）、argmax 翻转 0/15。
对照基线（results/s24b_official_cache_control.json）：官方链漂移 0.13–0.76、0 翻转。

**可引用结论**：GDN 混合架构的循环推理缓存不需要自写 cache 对象——
官方 Qwen3_5DynamicCache 分区复用 + 两个文档化适配（位置契约、占位 seed）
即可达到与训练语义一致的精确推理。该结论对 4B/27B 同架构可迁移。

## 3. 双臂设计要点

- 两臂同一原始权重、同数据序列（seed 2029、同 order、b2×ctx512）、
  同有效 token 预算 2.62M（2 epochs）、同 LoRA（r16/α32/dropout0.05，
  M 区 84 个模块 5.26M 参数）。
- 臂 A：单遍 CE。臂 B：循环 B=8，深度监督 K=2，
  loss = lm + β·SiLU(lm−lm_prev)，β=0.3；LoopUS 宽门（A_log=uniform[0.1,1.0]，
  已由 v3 存档范围证实）+ 恒等首圈开关 s=[+4,−4,…] + h₀ 重注入。
- **吞吐事实**：GDN torch 回退（无 fla）时 kernel launch 主导——NF4 与 bf16
  同速（15.8 vs 17.2 s/step）；batch 2 才有吞吐收益（27.8s/1024tok vs
  17.2s/512tok，+24%）。8GB laptop 卡上 batch 4 会明显劣化。
- 数据纪律：GSM8K train 三分（训练 6673 / 验证 400 / 退出校准 400），
  test 1319 零接触；manifest 含种子与 SHA256（data/gsm8k/s08/manifest.json）。

## 6. 4B 显式循环 vs 隐式循环 算力计数实测（2026-10-11，results/s27b_4b_compute.json）

**方法**：内容配平——同一 token 序列用两种成本模型计层前向（base 恒 32 层/token；
循环 20 + 12·d_i 其中 d_i 为路由器对该位置的退出深度，教师强制一次前向取得、
因果等价于自回归）。22 条文本（base 生成 12 / 自适应生成 6 / 验证集真实 rationale 4）。

**结果**：
- 路由器在真实 CoT 文本上的平均退出深度 d̄ ≈ **3.69–3.78**（vs 训练块统计 4.84）；
- 同内容每 token 成本：base 32 层 vs 循环 **65.4 层 → 2.04×**（gold/adaptive/base 三组一致 1.9–2.2×）；
- **翻本线 = 0.489**：隐式循环要总算力打平显式 CoT，必须把 token 数压到对方的 ≤49%；
- 现状：自适应生成的 token 数与 base 相当（~580 vs ~595），所以付 2×；
- **vs 自身固定 d8 的节省 = −43.6%**（65.4 vs 116 层/token，实测深度口径，
  优于此前 33–40% 的理论估计——真实文本退出更早）。
- 直接作答快测（隐式思考假设）：adaptive 模型 + 直接答案提示，6 题 cap48 token
  **0/6 strict**，全部跑满上限且格式漂移（续写 "Q: ..." 新题）——当前训练阶段
  模型不能绕开 CoT 作答，token 压缩路径尚不存在。

**结论**：自适应退出机制真实有效（退出深度 3.7/8、自身省 43.6%），
"隐式循环省于显式 CoT" 的必要条件是训练出**思考内化**（短输出同质量），
当前未训练该目标 → 两者叠加反而 2×。此为 S3 之后"思考内化"实验的立项依据。

## 9. 质量追平路线修订（2026-10-17）

S3 旧实现的两轮结果继续保留，但代码审计发现其质量梯度路径不足以支持“质量保持退出”结论：每圈 hidden 在更新后 detach，最终 loss 只使用最后一个监督圈的 CE，且硬阈值 `where(s>=tau)` 不能作为唯一学习路径。因此旧 S3 证明的是“router 能改变退出分布”，不是“router 学会无损退出”。

后续计划改为三道门：

1. **退出可训**：多档退出、平均深度下降；0.8B 已通过。
2. **质量追平**：用可微 continuation probability、quality warm-up、固定 d2 teacher/KL 和多深度一致性，达到 adaptive CE - fixed-best CE <= 0.005，strict/完成率不降。
3. **真实加速**：质量门通过后，才做 exit-skip、GDN 双状态稀疏推进、KV 共享/量化和 serving batching。

文献边界：MoR 的小规模 recursive capacity bottleneck、CALM/LayerSkip 的早退质量权衡支持该路线，但不直接证明 Qwen3.5-GDN 或 0.8B 的必然行为。新路线使用 Q1 router-only、Q2 M-block LoRA、Q3 M-block 更大 LoRA/全参的升级阶梯；每一级独立预算、checkpoint、看板指标和质量归档。执行仍暂停，等待明确训练启动指令。

## 13. Phase E：token 级 exit-skip 增量实现失败与根因（2026-10-18）

**过程**（s32/s32b/s32c，三轮二分）：修掉三个实现 bug（首 token 双重喂入/
prefill 缺失/KV 补条目 K 路径）后，tau=0 对照仍乱码 → 二分定位：
E 级 diff 0.46（bf16 噪声级正常），首 token logits 发散 24 → 发散源为
**跳过语义本身**，非缓存管线。

**根因**：G2 前置门禁（s31）验证的是**并行 hard**语义——退出位置仍以冻结
输入参与深圈 GDN/KV 计算，block 每圈跑全序列（无真实节省）。增量真跳过
让退出 token **完全缺席**深圈：GDN 递归状态是序列累加器，缺席改变后续
所有 token 的深圈历史 → 质量崩坏（"]]]"/"was was"）。两者语义不同，
G2 通过 ≠ 真跳过可行。与 V4 计划预警及 MoR 设计（routing 须与
recursion-wise caching 从头联合训练）一致。

**结论**：token 级真跳过需要部署语义训练（G2'，MoR 式），本轮不硬上。
**降级方案（自主决策）**：序列级自适应深度——每题按 prompt 聚合路由
决策选 d*，整题同深度生成（GDN 语义一致，无中途缺席）；质量下界已知
（fixed-d2=22/40）；省算力真实（d*≈2 → M 块省 ~75%）。实施见 §14。

## 14. Phase E 终局：真实跳过未通过 G2，根因闭环（2026-10-18）

**判别实验链**（s32/s32b/s32c/s32d + fp32 对照，六轮）：
1. 修掉三个实现 bug（首 token 双喂/prefill 缺失/K 补条目路径）后仍崩坏；
2. 序列级固定 d*（无任何退出/补条目）同样崩 → 排除退出语义；
3. hard/soft prefill 输出逐字节相同 → 排除 prefill-decode 语义混用；
4. 首 token 逐位一致（0.0），第二 token 发散 25 → bug 在首个增量步；
5. 逐层插桩：E0=0.19 → M2 跳 3.3 → D 层 4+（放大型发散）；
6. **fp32 重载 diff 不变（0.19/3.30）→ 排除数值噪声，确认为逻辑差**。

**根因**：transformers 5.3.0 的 GDN 单 token 增量更新
（recurrent_gated_delta_rule + causal_conv1d_update 回退实现）与分块重算
（chunk_gated_delta_rule）**数学不等价**——首个增量 token 在 E0 层即产生
0.19 真实语义差。裸 base（s24 验证对象）动力学不放大该差异故通过；
**arm B 训练出的高增益门控 M 块将其逐层指数放大**（0.19→logits 25），
生成从第二 token 起崩坏。

**Phase E 判定**：真实跳过（增量缓存路径）**未通过 G2**。按计划纪律，
部署默认退回 exact 全前缀重算（s30 路径，质量已验 23/40）。
可信的省算力结论保持为：Q1 soft 机制值 72% + s31 hard 门禁值
83.3%（tau=0.3，teacher-forced 口径）；均不冒充墙钟加速。

**修复选项（下轮拍板）**：
a. 部署语义一致性训练——训练期即用单步增量路径（Q2 扩展）；
b. 自写与 chunked 严格一致的单步 GDN 更新（展开 chunk 末步）；
c. 生成端维持全前缀重算 + 调度优化（接受慢但正确）。

## 16. 算力口径更正（2026-10-18，静态审计后）

对 §15 的“真实节省 61.7%”加注：**该数字暂标为 legacy_pending_revalidation，不得直接写入论文。** 静态审计发现三处口径问题：

1. 层数写错：实际结构是 E=4 / M=12 / D=8（24 层），固定深度单 token 层调用应为 `12+12d`（d2=36、d8=108），旧脚本用的是 `20+12d`（d2=44、d8=116）。

3. 语义：旧 s33 的 prefill 是 soft/全八圈，decode 是固定 d*；两者不是同一固定深度语义，不能称为 exact incremental。

**保留原记录不删除**，但正式引用前必须由 `COMPUTE_REALIZATION_AI_EXECUTION_PLAN_V1.md` 的 E1/E2 重新计数、重新计时，并以新结果覆盖结论表。旧的 `s31` 83.3%（teacher-forced 冻结近似，未真实跳过）同样只作前置参考。

## 17. E1 exact 增量 cache 正确性门通过 + 归因修正（2026-10-18，s41）

**方法**（`s41_e1_cache_gate.py`，5 combo × 3 题 × 教师强制 16 步）：
同深度 prefill+decode、首 token 来自 prefill 末位、绝对位置增量、
prefill 后按层 seed conv 占位（E 与各 M 深度）、物理层映射 `li-4` 断言、
forward hook 真实计数、参考序列由 full_recompute greedy 生成后教师强制回放。

| combo | 判定 | 语义翻转 | 并列翻转 | logits 最大差 | 状态对齐 |
|---|---|---|---|---|---|
| incremental d2 patch on | passed | 0 | 3 | 0.375 | 0.25 |
| incremental d2 patch **off** | passed | 0 | 2 | 0.391 | 0.25 |
| incremental d8 patch on | passed | 0 | 1 | 0.313 | 0.25 |
| incremental d8 patch **off** | passed | 0 | 1 | 0.297 | 0.25 |
| full_recompute d2 | passed | 0 | 0 | — | — |

公式校验：hook 实测 `calls_per_step = 36.0`，与 `E4+M12×d+D8 = 12+12d`
（d=2 → 36）精确一致；d8 → 108 一致。

**归因修正（重要，推翻 §14 的根因表述）**：seed 适配正确后，
patch on/off 的逐步差同为 0.27–0.31 噪声级且 16 步内有界、状态对齐 0.25
→ chunk 与 recurrent 内核差异**真实但有界**（bf16 运算次序级），不是
生成崩坏的主因。§13–§15 中"增量/分块不等价导致 logits 25 崩坏"的根因
表述不准确：真正主因是 **seed 适配缺失**——旧脚本在空 cache 上调用
seed22（no-op），transformers 的 `has_previous_state` 只读
`conv_states[last_linear_layer=22]`，E/M 分区 cache 不含层 22 → 每个
decode 步 E 层 GDN 走非历史分支、丢失 prefill 递归状态。s34 补丁当时
"治愈"生成，是因为它直接读 `recurrent_states[layer_idx]` 绕开了该坏分支，
属于**替代适配器**而非内核修复。

**修正后的两条工程结论**：
1. 分区 cache 部署必须先处理 `has_previous_state` 适配（占位或补丁二选一），
   这是 transformers 5.3.0 的真实陷阱，与内核选择无关；
2. GDN 单步增量与分块重写在 bf16 下有界漂移（≤0.4 logits、0.25 state），
   可部署；s34 补丁保留为可选适配器，E2 默认使用 patch on。

## 30. T-11 适配参数效率网格（2026-10-22/23，results/t11_param_eff.json，s54）

**问题（用户定义）**：同一技能，两模型各需多少**训练参数**才能学会。

**设计**：函数迭代任务 S^k(x)（k∈{1,2}，10 行映射表，k=2 需两次查表
↔ 循环第 2 圈）；prompt 65-66 tok；纯 completion 监督（末 2 token），
argmax 约束在数字+空格内；ctx80 bps4 lr3e-4 seed2029 每格 300 步
上限、acc≥0.95 早停；每 25 步固定 400 题评估（eval_set.pt 落盘，
跨格同题）；每格权重存档 ckpt_<arm>_r<r>.pt。
循环臂=S08 armB（旧 LoRA+门冻结，prior）叠加 fresh LoRA 双适配器同时
激活（PEFT set_adapter(['prior','fresh']) 已验证精确等于两 LoRA 之和）。

**过程修正（两次）**：① lr=1e-3 导致 loss 在 0.0002↔0.55 间震荡、
k1/k2 准确率反相跳 30pp（评估集每次重建+lr 过高）；改为 lr=3e-4 +
固定评估集后曲线单调。旧数据存档 archive_lr1e-3/（不复用）。
② 评估 400×80 全词表 logits ≈31GB OOM；改分批 50。

**结果（8 格，steps_to_90 = 首个 acc≥0.90 的评估点）**：
| r | n_train | dense | loop |
|---|---|---|---|
| 2 | 657,696 | 125 步 / .963 | 150 步 / .950 |
| 4 | 1,315,392 | **50 步** / .950 | 75 步 / .953 |
| 8 | 2,630,784 | 125 步 / .960 | **100 步** / .960 |
| 16 | 5,261,568 | **50 步** / .955 | 225 步 / .960 |

**判读（诚实）**：
- 全部 8 格在 300 步内都达 ≥95% —— **该技能对两臂都太容易，未形成
  可区分的参数量-难度前沿**；r=2 就能学会说明此任务不需要大适配器。
- 达阈步数在 r 上无单调趋势（dense: 125/50/125/50；loop: 150/75/100/225），
  与"更多参数更快"的朴素预期不符 → 说明测量点稀疏（25 步粒度）+ 技能
  饱和，当前数据不足以判定参数效率差异。
- **两臂 n_trainable 恒等**（同挂 M 区 12 层、同 r）——本设计测的是
  "同参数量下谁学得快"，不是"谁用更少参数"；后者需要让两臂覆盖不同
  可训练范围（如稠密臂挂全 24 层、循环臂挂 M 区 12 层），这才对应用户
  的原始主张。
- 结论：**本轮不适合作参数效率结论**，需改任务难度（k∈{2,3,4} 或更大
  置换域）+ 差异化可训练范围后重测。

## 30. T-11 裸 4B Base 的 CoT 开关对照（2026-10-22，s54）

**问题**：Qwen3.5-4B-Base 是否真的会"开启思维链"（此前项目内无此基线）。

**设计**：GSM8K s08-validation[0:100]（train 派生切片，无 test 污染）；
4-shot 取自 s08 train[0:4]；贪心；max_new=384；停止=EOS|行首 '\nQ:'。
cot_on=样例含 rationale；cot_off=样例只给 "The answer is #### N"。

**结果**：
| 模式 | strict | 生成长度 mean/median | 算术表达式/题 | 推理痕迹为零 | 耗时/题 |
|---|---|---|---|---|---|
| cot_on | **75/100** | 114.2 / 105.5 | 5.61 | 2% | 12.3s |
| cot_off | **26/100**（重算） | 6.5 / 6.0 | 0.00 | 100% | 1.8s |

- **4B Base 有真实、可切换的思维链**：cot_on 每题 5.6 个算式、>100 token、
  98% 自然完成；cot_off 只输出一个数字（6 token）、零推理痕迹。
- **CoT 质量收益巨大**：75 vs 26（+49pp）。这是 0.8B 完全不具备的性质

- **口径更正（已修）**：cot_off 首轮 strict=0 是评分 bug——prompt 末尾已含

  cot_on 不受影响（模型自行输出 `####`）。
- 长度结论：4B **不比** 0.8B 更长（114 vs 130 token），但它把 token 用在
  真推理上（5.6 个算式 vs 0.8B 的近零），即"4B 的思考是有效的短链"。

**对 4B 线的意义**：CoT 参照系成立且质量差异巨大（75 vs 26），
可以用来检验"循环内部深度能否替代这 75 分的显式链"——这是 0.8B 上
做不到的判定实验（0.8B 的 CoT 开关几乎无质量差异）。

## 33. T-13/T-14 现象的文献归因（2026-10-23，查证原始论文）

**核心结论：本轮"loop 臂无参数效率优势"与文献一致——循环模型的参数效率
是"从头训练期的归纳偏置"现象，不是"适配期"现象。**

1. Saunshi et al., *Reasoning with Latent Thoughts: On the Power of Looped
   Transformers*（arXiv:2502.17416）：从头训练时 (k⊗L) 循环模型在
   pp-hop induction（与本项目亲属多跳任务同构！）上 1 层循环 6 次=99.9%
   vs 2 层稠密=68.8%——但那是**任务即训练**的 from-scratch 设定；
   且其 Claim 2 指出循环模型"推理偏置强、记忆偏置弱"，而本项目
   480 例实体编号绑定任务偏记忆侧。
2. Kohli et al., *Loop, Think, & Generalize*（arXiv:2604.07822，COLM）：
   深度外推需要 (a)训练期 R>4 的迭代深度、(b)三阶段 grokking（10^4 量级
   epoch，远超本项目 200 步）、(c)hop 课程、(d)推理期加深；固定 d=2
   训练的可学习递归深度被训练深度封顶——解释 confirm_depth 只有 0.2-0.43。
3. Balesni et al., *Two-Hop Curse*（arXiv:2411.16353）：transformer 无 CoT
   直接学 A→C 组合天然困难——本项目答案为单 token（无 CoT），两臂
   都在"最难学"的设定下比赛。
4. *Verbose ListOps*（arXiv:2506.04907）：同计算嵌入干扰叙述后前沿模型
   崩塌（"context ≠ comprehension"）——解释 confirm_length 同 hop 却掉到
   0.16-0.24，且两臂同等崩（架构无关的通病）。
5. Fan et al., *Looped Transformers for Length Generalization*
   （arXiv:2409.15647）：循环迭代数与任务复杂度匹配（或自适应步数）才有
   泛化收益；本项目固定 d=2 无自适应，收益被压制——与 depth 轴 0.433 vs
   0.425 的噪声级差异一致。

**对本项目的推论**：要给循环臂公平机会需（按文献）①循环原生重训或大
预算继续训练；②hop 课程+grokking 级训练时长；③动态/随机循环深度训练；
④训练期干扰多样性。当前"稠密预训练+LoRA 适配"不继承循环原生训练的
参数效率——这是可发表的诚实负结果，且与文献自洽。

## 31. 文献调研：循环深度的算力测量方法/指标/训练集（2026-10-22）

**来源**（全文核读）：LoopUS arXiv 2605.11011（本项目方法直系来源）；
Huginn/Geiping et al. arXiv 2502.05171（循环深度规模化标尺）。

**LoopUS 的测量框架**：
- 训练：FineWeb-Edu **3B token 通用语料**（ctx1024），非任务数据；
- 评测：lm-eval-harness 零样本套件（Wiki/LAMBADA ppl + MMLU/HS/ARC-E/C/
  PIQA/WG/OBQA）——**无 GSM8K 型生成任务**；
- 算力指标：**accuracy-vs-迭代数曲线**（Figure 5）+ 自适应平均停止深度
  （3.39/8 圈，confidence 阈值 q_th，逐 token 停止，KV cache 原生）；
- 主张：+1.6~2.2 平均分的**质量增益**，"自适应停止控制额外开销"——
  **从不主张比原模型省推理算力**。

**Huginn 的测量框架**：
- 训练：**从头训练** 800B token（代码+数学偏重的自配混合），训练时迭代数
  从 log-normal Poisson 随机采样（均值 r̄=32）——模型从预训练起就依赖深度；
- 评测：lm-eval 套件 + GSM8K（零样本/8-shot CoT）+ MATH/Minerva + MBPP/
  HumanEval；
- 算力指标：**FLOPs 等效参数**框架——3.5B 参数 r=32 时有效深度 132 层，
  "消耗接近 32B 稠密模型的 FLOPs，质量可达 50B 等效算力水平"；
  报告形式为 "Ours(r=4/8/16/32)" 的 accuracy-vs-r；
- **黄金基线（Table 4）**：同设置训练的**非循环孪生**（同一架构、核心块
  单遍）——r=32 vs 孪生：ARC-C 38.2 vs 27.0，GSM8K CoT 42.1 vs 2.2；
  r=1 时模型塌到 24.1/0.0（深度收益 14~42pp，因模型被训练为依赖深度）。

**与我们做法的对照（三个差距）**：
1. 训练集：我们 GSM8K rationale（~130 tok 短链）+wiki 7:3；LoopUS 纯
   通用语料；Huginn 代码/数学偏重 800B。"深度无收益"可能与短链训练
   数据直接相关（rationale 是单步推理，潜空间无需多圈）。
2. 基线：Huginn 的非循环孪生是正确公平基线；我们的 armA 近似孪生但
   双方都在无深度依赖的数据上训练。
3. 指标：文献标准是 accuracy-vs-r 曲线 + 孪生对比；我们自造的
   层调用计数/token-layer 合成账不在文献体系中。
- **关键发现：文献中"省算力"主张全部是参数效率角度（少参数+多重复
  计算≈大模型质量），或 vs 自身满深度的节省（MoR）。没有一篇主张
  "推理时比同质量单遍模型更省"——我们一直在测一个文献中无人主张的命题。**

## 32. P1-0 ProsQA 基线：CoT 反而伤害 0.8B（2026-10-23，s56）

**配置**：Qwen3.5-0.8B-Base bf16；prosqa_valid 全 300 题（合成，无污染）；
4-shot 取 prosqa_train[0:4]；贪心；停止=EOS|'\nQ:'；评分=最后一个
'X is a Y' 的类别精确匹配。

**结果（配对 n=300）**：
| 模式 | strict | 长度 mean/median | 耗时/题 | prompt tok |
|---|---|---|---|---|
| cot_on（示范推理链） | **74/300 = 24.7%** | 53.5 / 45 | 4.2s | 1872 |
| cot_off（示范只给结论） | **154/300 = 51.3%** | 9.7 / 10 | 1.7s | 1737 |

配对差（off−on）= **+26.7pp，CI [+19.3, +34.0]**，不含 0；翻转细分：
两者都对 42、仅 on 对 32、**仅 off 对 112**。

**判读**：
1. **CoT 在 ProsQA 上对 0.8B 是负作用**，且幅度巨大（翻倍）。
2. 文本证据：cot_on 生成的"推理链"是**编造的边**（如 gold=lempus，模型写
   "Tom is a terpus. Every terpus is a fompus…"——这些规则在题干里可能不
   存在或顺序错误）；9.7 token 的直接作答反而命中率翻倍，说明 0.8B 能
   从 180 词的规则网里"直觉抽取值"，但一旦要求显式多步推导就出错。
3. ent_ok_rate：cot_off=1.00 vs cot_on=0.917——连主语都更容易搞错。
4. 这与 Coconut 论文的前提**相反**：该论文在 GPT-2 规模上 CoT 达 77.5%、
   潜推理 97%；我们的 0.8B 在 CoT 下只有 24.7%。差异来源：Coconut 是
   **在 ProsQA 上专门训练过的**（CoT 微调），而这里是**零样本 few-shot**。
   ⇒ 不能直接引用其数字作参照。

**对 P1-1 的影响（关键）**：G1 门禁原本设计为"训练后 strict(d8)−strict(d1)
≥10pp"。当前 cot_on 基线 24.7% 远低于 cot_off 51.3%，说明**"显式推理链"
这条路在 0.8B 上已经失败**——但这恰恰给循环深度留出了理论空间：若潜空间
迭代能捕获"直觉抽取"之外的组合结构，它是**替代**失败的显式 CoT，而
不是与之比较。P1-1 的参照应改为 **cot_off（51.3%）**，即"循环能否超过
直接作答"。

**需用户决策**：是否按此修正 P1-1 的目标（超过 51.3% 的直接作答基线），
还是先补一个"0.8B 在 ProsQA 上训练过的 CoT 基线"（需训练，成本上升）。
